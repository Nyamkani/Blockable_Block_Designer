# Blockable 블록·조합 규칙 편집기 사용 설명서

문서 버전: `0.2`  
대상 프로그램: Blockable Rule Editor `0.2.0`

---

## 1. 프로그램 소개

Blockable 블록·조합 규칙 편집기는 Blockable 웹 게임에서 사용할 다음 데이터를
시각적으로 설계하고 JSON 파일로 저장하는 도구입니다.

- 블록의 분류(Type)
- 블록 색상
- 블록 모양
- 블록 자체 효과
- 여러 블록으로 구성된 조합식
- 조합식이 완성되었을 때 발생하는 효과

이 프로그램은 Blockable 게임 자체가 아닙니다. 전투 진행, 체력 계산, 블록 뽑기,
조합 판정 등은 수행하지 않으며 게임에서 읽어 사용할 규칙 데이터만 제작합니다.

## 2. 설치 및 실행 방법

### 2.1 필요 환경

- Python 3.12 이상
- Python 표준 GUI 라이브러리 `tkinter`

이 문서의 모든 경로는 프로젝트 최상위 폴더를 기준으로 한 상대 경로입니다.
프로젝트 폴더 이름이 `Blockable_Design_Program`이라면 다음 파일과 폴더가 보이는
위치가 프로젝트 최상위 폴더입니다.

```text
Blockable_Design_Program/
├── README.md
├── pyproject.toml
├── docs/
├── examples/
├── src/
└── tests/
```

터미널 또는 명령 프롬프트에서 먼저 프로젝트 최상위 폴더로 이동해야 합니다.
프로젝트를 저장한 위치에 따라 상위 경로는 달라질 수 있습니다.

### 2.2 Linux에서 실행

터미널을 열고 프로젝트 폴더로 이동합니다.

```bash
cd Blockable_Design_Program
```

현재 위치에 `pyproject.toml`과 `src` 폴더가 있는지 확인한 다음 실행합니다.

```bash
PYTHONPATH=src python -m blockable_rule_editor
```

배포판에 따라 `python` 대신 `python3` 명령을 사용해야 할 수 있습니다.

```bash
PYTHONPATH=src python3 -m blockable_rule_editor
```

### 2.3 Windows PowerShell에서 실행

파일 탐색기에서 프로젝트 폴더를 연 뒤 주소 표시줄에 `powershell`을 입력하면
해당 폴더에서 PowerShell을 열 수 있습니다. 다른 위치에서 열었다면 프로젝트
폴더로 이동합니다.

```powershell
cd Blockable_Design_Program
```

PowerShell에서 다음 명령을 차례로 실행합니다.

```powershell
$env:PYTHONPATH = "src"
python -m blockable_rule_editor
```

Windows Python Launcher를 사용하는 경우 다음과 같이 실행할 수도 있습니다.

```powershell
$env:PYTHONPATH = "src"
py -3.12 -m blockable_rule_editor
```

`PYTHONPATH` 설정은 현재 PowerShell 창에만 적용됩니다. 새 PowerShell 창에서
실행할 때는 다시 설정해야 합니다.

### 2.4 Windows 명령 프롬프트에서 실행

명령 프롬프트에서 프로젝트 폴더로 이동한 다음 명령을 실행합니다.

```bat
cd Blockable_Design_Program
set PYTHONPATH=src
python -m blockable_rule_editor
```

Python Launcher를 사용하는 경우 마지막 명령을 다음과 같이 바꿀 수 있습니다.

```bat
py -3.12 -m blockable_rule_editor
```

### 2.5 정상 실행 확인

정상적으로 실행되면 `Blockable 블록·조합 규칙 편집기` 창이 열립니다. 다음
명령으로 설치된 Python 버전을 먼저 확인할 수도 있습니다.

Linux:

```bash
python3 --version
```

Windows PowerShell 또는 명령 프롬프트:

```powershell
python --version
```

또는:

```powershell
py -3.12 --version
```

### 2.6 tkinter 오류가 발생하는 경우

다음과 같은 오류가 나오면 운영체제에 tkinter가 설치되어 있는지 확인합니다.

```text
ModuleNotFoundError: No module named 'tkinter'
```

Ubuntu 또는 Debian 계열 Linux:

```bash
sudo apt update
sudo apt install python3-tk
```

Fedora 계열 Linux:

```bash
sudo dnf install python3-tkinter
```

Windows에서는 [Python 공식 배포판](https://www.python.org/downloads/windows/)에
tkinter가 일반적으로 포함됩니다. 오류가 발생하면 Python 설치 관리자를 다시
실행하고 `Modify`를 선택한 뒤 `tcl/tk and IDLE` 항목을 활성화합니다. Microsoft
Store 또는 별도 배포판의 Python을 사용 중이라면 공식 배포판 설치를 권장합니다.

설치 또는 수정 후 새 터미널을 열고 프로그램 실행 명령을 다시 입력합니다.

### 2.7 테스트 실행

테스트는 프로젝트 최상위 폴더에서 실행합니다.

Linux:

```bash
PYTHONPATH=src python3 -m pytest -q
```

Windows PowerShell:

```powershell
$env:PYTHONPATH = "src"
python -m pytest -q
```

Windows 명령 프롬프트:

```bat
set PYTHONPATH=src
python -m pytest -q
```

`No module named pytest` 오류가 나오면 개발용 의존성을 먼저 설치합니다.

Linux:

```bash
python3 -m pip install -e ".[dev]"
```

Windows:

```powershell
python -m pip install -e ".[dev]"
```

## 3. 권장 작업 순서

규칙 데이터는 서로 참조하므로 다음 순서로 작업하는 것이 좋습니다.

1. 새 프로젝트를 만듭니다.
2. 프로젝트 이름과 규칙 세트 이름을 입력합니다.
3. 필요한 Type을 만듭니다.
4. 기본 색상을 확인하고 필요한 색상을 추가합니다.
5. 블록을 만들고 모양과 효과를 설정합니다.
6. 조합식을 만들고 블록을 배치합니다.
7. 조합 효과를 설정합니다.
8. 전체 검사를 실행합니다.
9. 오류를 수정하고 경고를 확인합니다.
10. JSON 파일로 저장합니다.

Type과 색상을 먼저 준비해야 블록에서 올바르게 선택할 수 있습니다. 블록을 먼저
완성해야 조합식 격자에 해당 블록을 배치할 수 있습니다.

## 4. 화면 구성

프로그램 상단에는 다음 탭이 있습니다.

| 탭 | 용도 |
|---|---|
| 프로젝트 | 새 프로젝트, 열기, 저장 및 메타데이터 관리 |
| Type 관리 | 블록 분류 추가, 수정, 삭제 |
| 색상 관리 | 블록 색상 추가, 수정, 삭제 |
| 블록 편집기 | 블록 정보, 모양 및 자체 효과 편집 |
| 조합식 편집기 | 조건 슬롯, 기본 효과 및 조건부 보너스 편집 |
| 색상 시너지 | 모든 조합식에 적용할 공통 시너지 편집 |
| 검사 결과 | 전체 데이터의 오류와 경고 확인 |

상단 메뉴의 `파일`에서 새 프로젝트, 열기, 저장, 다른 이름으로 저장 및 종료를
실행할 수 있습니다. `전체 검사` 메뉴로 현재 프로젝트를 검사할 수 있습니다.

## 5. 프로젝트 관리

### 5.1 새 프로젝트 만들기

1. `프로젝트` 탭에서 `새 프로젝트` 버튼을 누릅니다.
2. 또는 상단 메뉴에서 `파일 → 새 프로젝트`를 선택합니다.
3. 프로젝트 이름과 규칙 세트 이름을 입력합니다.

새 프로젝트에는 빨강, 주황, 노랑, 초록, 파랑, 남색, 보라의 기본 7색과 기본
효과 정의가 포함됩니다. Type, 블록, 조합식은 비어 있습니다.

저장하지 않은 변경 내용이 있을 때 새 프로젝트를 만들면 변경 내용을 버릴지
묻는 창이 표시됩니다.

### 5.2 프로젝트 열기

1. `프로젝트` 탭의 `JSON 열기` 버튼을 누릅니다.
2. 또는 `파일 → 열기…`를 선택합니다.
3. 열려는 JSON 파일을 선택합니다.

파일을 열 때 다음 내용을 검사합니다.

- JSON 문법
- `schema_version`
- ID와 필수 입력값
- Type, 색상, 블록, 효과 참조
- 블록 모양
- 조합식 배치와 겹침
- 효과 파라미터

오류가 있는 파일은 열리지 않으며 실패 원인이 표시됩니다. 현재 프로그램에서
현재 저장 스키마 버전은 `1.1.0`입니다. 기존 `1.0.0` 파일도 열 수 있으며,
정확한 블록 슬롯으로 자동 변환됩니다.

### 5.3 프로젝트 저장

처음 저장할 때는 저장할 위치와 파일명을 선택합니다. 기본 파일명은 다음과
같습니다.

```text
blockable_rules.json
```

이후에는 `저장`을 누르면 같은 파일에 저장됩니다. 다른 파일로 보관하려면
`파일 → 다른 이름으로 저장…`을 사용합니다.

저장 시 전체 검사가 자동으로 실행됩니다.

- 오류가 있으면 저장할 수 없습니다.
- 경고만 있으면 경고를 확인한 후 저장할 수 있습니다.
- 저장 좌표는 자동으로 좌상단 `(0, 0)` 기준으로 정규화됩니다.
- 저장 파일은 UTF-8 JSON과 들여쓰기 2칸을 사용합니다.

프로그램 제목 앞의 `*` 표시는 아직 저장되지 않은 변경 내용이 있다는 뜻입니다.

### 5.4 키보드 단축키

| 단축키 | 기능 |
|---|---|
| `Ctrl+N` | 새 프로젝트 |
| `Ctrl+O` | JSON 열기 |
| `Ctrl+S` | 저장 |

## 6. Type 관리

Type은 사용자가 정의하는 블록 분류입니다. `normal`, `unique`, `curse`,
`weapon` 같은 ID를 자유롭게 만들 수 있습니다.

### 6.1 Type 추가

1. `Type 관리` 탭을 엽니다.
2. `추가` 버튼을 누릅니다.
3. ID, 이름, 설명을 입력합니다.
4. `확인`을 누릅니다.

ID는 영문 소문자 `snake_case` 형식을 사용합니다.

올바른 예:

```text
normal
unique
core_block
magic_weapon
```

올바르지 않은 예:

```text
Normal
core-block
저주
```

### 6.2 Type 수정

1. 목록에서 Type을 선택합니다.
2. `수정` 버튼을 누릅니다.
3. 값을 변경하고 `확인`을 누릅니다.

Type ID를 변경하면 해당 Type을 사용하던 블록의 참조도 함께 변경됩니다.

### 6.3 Type 삭제

목록에서 Type을 선택하고 `삭제`를 누릅니다. 블록에서 사용 중인 Type은 삭제할
수 없으며 사용 중인 블록 ID가 안내됩니다.

## 7. 색상 관리

새 프로젝트에는 다음 기본 7색이 포함됩니다.

| ID | 이름 | HEX |
|---|---|---|
| `red` | 빨간색 | `#E53935` |
| `orange` | 주황색 | `#FB8C00` |
| `yellow` | 노란색 | `#FDD835` |
| `green` | 초록색 | `#43A047` |
| `blue` | 파란색 | `#1E88E5` |
| `indigo` | 남색 | `#3949AB` |
| `purple` | 보라색 | `#8E24AA` |

### 7.1 색상 추가

1. `색상 관리` 탭을 엽니다.
2. `추가` 버튼을 누릅니다.
3. ID, 이름, HEX 값을 입력합니다.
4. `확인`을 누릅니다.

HEX 값은 `#RRGGBB` 형식이어야 합니다.

```text
#E53935
#12ABEF
```

### 7.2 색상 수정

목록에서 색상을 선택하고 `수정`을 누릅니다. 색상 ID를 변경하면 해당 색상을
사용하던 블록의 참조도 함께 변경됩니다.

### 7.3 색상 삭제

목록에서 색상을 선택하고 `삭제`를 누릅니다. 블록이 사용 중인 색상은 삭제할 수
없으며 사용 중인 블록 ID가 안내됩니다.

## 8. 블록 편집

블록 편집기 화면은 다음 세 영역으로 구성됩니다.

- 왼쪽: 블록 목록과 추가·복제·삭제 버튼
- 가운데: 블록 모양 격자
- 오른쪽: 블록 속성과 효과

### 8.1 블록 만들기

1. Type을 하나 이상 준비합니다.
2. `블록 편집기` 탭을 엽니다.
3. 왼쪽 아래의 `추가` 버튼을 누릅니다.
4. 오른쪽에서 ID, 이름, Type, 색상을 입력합니다.
5. 가운데 격자를 클릭해 블록 모양을 만듭니다.
6. 필요하면 태그, 회전·반전 허용, 설명과 효과를 설정합니다.

새 블록은 한 칸 모양으로 만들어집니다. 격자의 빈 칸을 클릭하면 칸이 추가되고,
활성화된 칸을 다시 클릭하면 제거됩니다.

### 8.2 블록 모양 규칙

- 블록에는 최소 한 칸이 있어야 합니다.
- 모든 칸은 상하좌우 방향으로 연결되어야 합니다.
- 대각선으로만 닿는 칸은 연결된 것으로 보지 않습니다.
- 저장할 때 모양의 좌상단이 자동으로 `(0, 0)`이 됩니다.

예를 들어 다음 모양은 연결된 L자 블록입니다.

```text
■□
■■
```

다음 모양은 대각선으로만 연결되어 있어 오류입니다.

```text
■□
□■
```

### 8.3 블록 속성

| 항목 | 설명 |
|---|---|
| ID | 프로젝트에서 블록을 식별하는 고유 ID |
| 이름 | 편집기와 게임에서 표시할 이름 |
| Type | Type 관리에서 만든 분류 |
| 색상 | 색상 관리에 등록된 색상 |
| 태그 | 쉼표로 구분하는 검색·분류용 값 |
| 회전 허용 | 조합식에서 이 블록을 회전할 수 있는지 여부 |
| 좌우 반전 허용 | 조합식에서 이 블록을 반전할 수 있는지 여부 |
| 설명 | 편집자를 위한 블록 설명 |

태그 입력 예:

```text
weapon, fire, starter
```

### 8.4 블록 복제

1. 블록 목록에서 원본 블록을 선택합니다.
2. `복제` 버튼을 누릅니다.
3. 생성된 복사본의 ID와 이름을 수정합니다.

복사본 ID에는 `_copy`, 이름에는 `복사본`이 추가됩니다. 프로젝트의 다른 ID와
겹치지 않도록 반드시 확인합니다.

### 8.5 블록 삭제

블록 목록에서 블록을 선택하고 `삭제`를 누릅니다. 조합식에서 사용 중인 블록은
삭제할 수 없으며 해당 조합식 ID가 표시됩니다. 먼저 조합식에서 해당 인스턴스를
삭제해야 합니다.

## 9. 효과 편집

블록 자체 효과와 조합 완성 효과는 같은 방식으로 편집합니다.

### 9.1 효과 추가

1. 블록 또는 조합식을 선택합니다.
2. 오른쪽 `효과` 영역에서 `추가`를 누릅니다.
3. 효과 ID를 선택합니다.
4. 실행 순서를 입력합니다.
5. Parameters를 JSON 객체로 입력합니다.
6. 필요한 경우 설명을 입력합니다.
7. `확인`을 누릅니다.

피해 효과의 Parameters 예:

```json
{
  "amount": 10,
  "target": "enemy"
}
```

Parameters에는 반드시 JSON 객체를 입력해야 합니다. 문자열 키는 큰따옴표로
감싸고 마지막 항목 뒤에는 쉼표를 넣지 않습니다.

잘못된 예:

```text
{'amount': 10}
```

올바른 예:

```json
{
  "amount": 10
}
```

### 9.2 효과 순서

`순서`는 여러 효과가 있을 때 실행 순서를 나타내는 정수입니다. 일반적으로
`0`, `1`, `2` 순서로 지정합니다.

### 9.3 효과 수정 및 삭제

- 목록에서 효과를 선택하고 `수정`을 누르거나 효과를 더블클릭합니다.
- 목록에서 효과를 선택하고 `삭제`를 누르면 제거됩니다.

효과 정의에 필수 파라미터가 있으면 반드시 입력해야 합니다. 자료형이나 최솟값이
맞지 않으면 전체 검사에서 오류로 표시됩니다.

## 10. 조합식 편집

조합식 편집기는 다음 영역으로 구성됩니다.

- 왼쪽 위: 조합식 목록
- 왼쪽 아래: 배치할 블록 목록
- 가운데: 조합식 배치 격자
- 오른쪽: 조합식 속성과 완성 효과

### 10.1 조합식 만들기

1. `조합식 편집기` 탭을 엽니다.
2. 조합식 목록 아래의 `추가`를 누릅니다.
3. 오른쪽에서 ID와 이름을 입력합니다.
4. 왼쪽 아래 `배치할 블록` 목록에서 블록을 선택합니다.
5. 가운데 격자의 원하는 위치를 클릭합니다.
6. 같은 방법으로 필요한 블록을 계속 배치합니다.
7. 조합 전체 회전·반전 인정 여부와 효과를 설정합니다.

같은 블록을 여러 번 배치할 수 있습니다. 조합식 안에 배치된 각각의 블록은
`piece_1`, `piece_2` 같은 별도 인스턴스 ID를 가집니다.

### 10.2 배치된 블록 선택

격자에서 이미 배치된 블록의 칸을 클릭하면 해당 인스턴스가 선택됩니다. 선택된
인스턴스는 진한 테두리로 표시되고 격자 아래에 ID와 블록 ID가 표시됩니다.

### 10.3 슬롯 허용 조건

배치된 블록은 조합식 도면의 모양 템플릿 역할도 합니다. 격자에서 인스턴스를
선택한 뒤 `선택 슬롯의 허용 조건`에서 다음 중 하나를 지정할 수 있습니다.

| 조건 | 의미 |
|---|---|
| 정확한 블록 | 배치할 때 선택한 블록 ID만 허용 |
| 임의 블록 | 같은 모양의 어떤 블록이든 허용 |
| 같은 Type | 지정한 Type이며 같은 모양인 블록 허용 |
| 같은 색상 | 지정한 색상이며 같은 모양인 블록 허용 |
| 태그 | 지정 태그가 있으며 같은 모양인 블록 허용 |

1. 격자에서 블록 인스턴스를 선택합니다.
2. 슬롯 조건 종류를 선택합니다.
3. Type, 색상 또는 태그가 필요한 조건이면 값을 선택하거나 입력합니다.
4. `조건 적용`을 누릅니다.

예를 들어 의자 조합의 두 자리를 모두 `같은 Type: normal`로 설정하면 특정
색상의 블록 ID를 일일이 지정하지 않고도 normal Type 블록을 받을 수 있습니다.
다만 실제 블록의 회전·반전된 모양은 해당 슬롯의 템플릿 모양과 같아야 합니다.

### 10.4 블록 회전

1. 격자에서 배치된 블록을 선택합니다.
2. `선택 회전` 버튼을 누릅니다.

누를 때마다 90도씩 회전합니다. 블록에서 `회전 허용`이 꺼져 있거나 회전 결과가
다른 블록과 겹치면 회전할 수 없습니다.

### 10.5 블록 반전

1. 격자에서 배치된 블록을 선택합니다.
2. `선택 반전` 버튼을 누릅니다.

블록에서 `좌우 반전 허용`이 켜져 있어야 합니다. 반전 결과가 다른 블록과 겹치면
반전할 수 없습니다.

### 10.6 배치된 블록 삭제

격자에서 블록을 선택한 후 `선택 삭제` 버튼을 누릅니다.

### 10.7 겹침 처리

새 블록을 놓거나 기존 블록을 회전·반전했을 때 다른 인스턴스와 한 칸이라도
겹치면 해당 작업은 거부됩니다.

### 10.8 조합식 속성

| 항목 | 설명 |
|---|---|
| ID | 프로젝트에서 조합식을 식별하는 고유 ID |
| 이름 | 조합식 표시 이름 |
| 태그 | 쉼표로 구분하는 분류용 값 |
| 조합 전체 회전 인정 | 등록 방향을 회전한 배치도 게임에서 인정할지 여부 |
| 조합 전체 반전 인정 | 등록 모양을 반전한 배치도 게임에서 인정할지 여부 |
| 설명 | 편집자를 위한 조합식 설명 |
| 효과 | 조합이 완성되면 항상 발생할 기본 효과 |
| 조건부 보너스 | 같은 색 등 추가 조건이 맞을 때 발생할 효과 |

`조합 전체 회전 인정`과 `조합 전체 반전 인정`은 JSON 규칙에 저장되는 설정입니다.
실제 게임에서 이를 판정하는 로직은 본 게임에서 구현해야 합니다.

### 10.9 조건부 보너스

조합식 오른쪽의 `조건부 보너스`에서 해당 조합에만 적용되는 추가 효과를 만들 수
있습니다.

1. `추가`를 누릅니다.
2. `모두 같은 색`, `특정 색 개수` 등의 조건을 선택합니다.
3. 필요한 경우 조건 Parameters를 JSON 객체로 입력합니다.
4. 조건이 맞을 때 추가할 효과를 하나 이상 등록합니다.
5. `확인`을 누릅니다.

조건별 Parameters 예:

```json
{}
```

`모두 같은 색`, `모두 다른 색`, `모두 같은 Type`은 빈 객체를 사용합니다.

```json
{
  "color_id": "red"
}
```

`특정 색 포함`에 사용합니다.

```json
{
  "color_id": "red",
  "count": 2
}
```

`특정 색 개수`에 사용합니다.

```json
{
  "color_ids": ["red", "blue"]
}
```

`지정 색상 구성`에 사용합니다.

```json
{
  "count": 3
}
```

`블록 개수`에 사용합니다.

```json
{
  "tag": "weapon"
}
```

`태그 일치`에 사용합니다.

### 10.10 현재 버전의 이동 방법

현재 버전은 배치된 인스턴스를 드래그하여 이동하는 기능을 제공하지 않습니다.
위치를 변경하려면 해당 인스턴스를 삭제한 뒤 원하는 위치에 다시 배치합니다.

## 11. 공통 색상 시너지

`색상 시너지` 탭에서는 특정 조합식에 종속되지 않고 모든 완성 조합에 적용할
공통 보너스를 정의합니다.

예:

- 모든 참여 블록이 빨간색이면 공격 보너스
- 빨간색 블록이 2개면 추가 피해
- 빨강·파랑 구성이라면 공격과 방어 증가
- 모든 참여 블록의 색이 다르면 추가 블록 획득

### 11.1 시너지 추가

1. `색상 시너지` 탭에서 `추가`를 누릅니다.
2. 영문 ID, 한글 표시 이름과 설명을 입력합니다.
3. 조건 종류와 조건 Parameters를 입력합니다.
4. 조건이 맞을 때 발생할 효과를 하나 이상 추가합니다.
5. `확인`을 누릅니다.

### 11.2 시너지 수정·일시 해제·삭제

- 목록에서 시너지를 선택하고 `수정`을 누르거나 더블클릭합니다.
- `사용/해제`를 누르면 규칙을 삭제하지 않고 적용 여부를 변경합니다.
- `삭제`를 누르면 프로젝트에서 완전히 제거합니다.

조합식의 기본 효과, 조합식 조건부 보너스, 공통 색상 시너지는 서로 별도로
저장됩니다. 최종 합산 순서와 중첩 방식은 본 게임의 규칙 처리기가 구현해야
합니다.

## 12. 전체 검사

`검사 결과` 탭에서 `검사 실행`을 누르거나 상단의 `전체 검사`를 선택합니다.

검사 결과에는 다음 정보가 표시됩니다.

- 등급: `ERROR` 또는 `WARNING`
- 위치: 문제가 있는 Type, 색상, 블록 또는 조합식
- 내용: 문제 설명

### 12.1 오류

오류가 하나라도 있으면 저장할 수 없습니다. 대표적인 오류는 다음과 같습니다.

- ID 또는 이름 누락
- 잘못된 ID 형식
- 중복 ID
- 존재하지 않는 Type, 색상, 블록 또는 효과 참조
- 비어 있거나 분리된 블록 모양
- 중복된 블록 칸 좌표
- 허용되지 않은 회전 또는 반전
- 조합식 인스턴스 겹침
- 잘못된 회전값
- 효과 필수 파라미터 누락
- 효과 파라미터 자료형 또는 범위 오류
- 블록이 하나도 없는 조합식
- 존재하지 않는 슬롯 Type 또는 색상
- 지원하지 않는 슬롯·보너스 조건
- 비어 있는 조건부 효과 또는 시너지 효과

### 12.2 경고

경고는 확인 후 저장할 수 있습니다. 대표적인 경고는 다음과 같습니다.

- 사용되지 않는 Type
- 사용되지 않는 색상
- 조합식에서 사용되지 않는 블록
- 자체 효과가 없는 블록
- 모양, Type, 색상이 같은 블록
- 최소 `3×3` 거푸집보다 큰 조합식

프로젝트를 처음 구성하는 동안에는 사용되지 않은 색상과 Type에 대한 경고가
표시될 수 있습니다. 의도한 데이터라면 경고를 확인하고 저장할 수 있습니다.

## 13. 처음부터 예제 만들기

다음은 붉은 1칸 블록 두 개로 조합식을 만드는 간단한 예입니다.

### 13.1 Type 만들기

`Type 관리 → 추가`에서 다음 값을 입력합니다.

```text
ID: normal
이름: 일반
설명: 일반 블록
```

### 13.2 블록 만들기

`블록 편집기 → 추가`에서 다음과 같이 설정합니다.

```text
ID: red_dot
이름: 붉은 점
Type: normal
색상: red
```

모양은 기본 한 칸을 그대로 사용합니다.

효과가 필요하면 `효과 → 추가`에서 다음과 같이 입력합니다.

```text
효과: deal_damage
순서: 0
```

```json
{
  "amount": 1
}
```

### 13.3 조합식 만들기

1. `조합식 편집기 → 추가`를 누릅니다.
2. ID를 `red_pair`, 이름을 `붉은 쌍`으로 지정합니다.
3. `배치할 블록`에서 `red_dot`을 선택합니다.
4. 격자의 서로 인접한 두 칸을 차례로 클릭합니다.
5. 조합 효과로 `deal_damage`를 추가합니다.

조합 효과 Parameters 예:

```json
{
  "amount": 5
}
```

### 13.4 같은 색 보너스 추가

1. 조합식 격자에서 첫 번째 인스턴스를 선택합니다.
2. 슬롯 조건을 `같은 Type`, 값을 `normal`로 지정하고 `조건 적용`을 누릅니다.
3. 두 번째 인스턴스에도 같은 조건을 적용합니다.
4. `조건부 보너스 → 추가`를 누릅니다.
5. 조건을 `모두 같은 색`, Parameters를 `{}`로 지정합니다.
6. 추가 피해 효과를 등록합니다.

이제 두 슬롯에는 같은 모양의 normal 블록을 사용할 수 있고, 실제 참여 블록의
색상이 같으면 추가 효과가 발생하는 규칙 데이터가 저장됩니다.

### 13.5 검사와 저장

1. `전체 검사`를 실행합니다.
2. 오류가 있다면 해당 데이터를 수정합니다.
3. 경고를 확인합니다.
4. `Ctrl+S`를 누릅니다.
5. 파일명을 `blockable_rules.json`으로 저장합니다.

## 14. 자주 발생하는 문제

### 14.1 저장 버튼을 눌러도 저장되지 않습니다

`검사 결과` 탭에서 `ERROR` 항목을 확인합니다. 오류를 모두 수정해야 저장할 수
있습니다.

### 14.2 Type 또는 색상을 삭제할 수 없습니다

해당 Type 또는 색상을 사용하는 블록이 있습니다. 안내된 블록의 Type이나 색상을
다른 값으로 변경한 뒤 다시 삭제합니다.

### 14.3 블록을 삭제할 수 없습니다

해당 블록을 사용하는 조합식이 있습니다. 안내된 조합식에서 해당 블록
인스턴스를 먼저 삭제합니다.

### 14.4 회전 또는 반전이 되지 않습니다

다음 사항을 확인합니다.

- 블록 속성에서 해당 변환이 허용되어 있는지
- 변환 결과가 다른 블록 인스턴스와 겹치지 않는지

### 14.5 효과 Parameters 입력 오류가 발생합니다

Parameters는 Python 딕셔너리가 아니라 올바른 JSON 객체여야 합니다.

- 키와 문자열은 큰따옴표를 사용합니다.
- `True`, `False`, `None` 대신 `true`, `false`, `null`을 사용합니다.
- 마지막 항목 뒤에 쉼표를 넣지 않습니다.

### 14.6 JSON 파일을 열 수 없습니다

파일의 JSON 문법과 `schema_version`을 확인합니다. 현재 버전은
`"schema_version": "1.0.0"`과 `"schema_version": "1.1.0"`을 지원합니다.
데이터 참조나 배치 오류가 있는 파일은 열리지 않습니다.

## 15. 현재 버전의 범위와 제한

현재 버전은 규칙 편집 MVP이며 다음 기능은 제공하지 않습니다.

- 실제 전투 또는 조합 판정 실행
- 체력에 따른 거푸집 축소
- 블록 드래그 이동
- 격자 확대·축소
- 효과 정의를 화면에서 추가·수정하는 기능
- 오류 항목을 더블클릭해 편집 화면으로 바로 이동하는 기능
- 조합 자동 탐색 및 밸런싱

효과 정의 자체를 변경해야 한다면 현재는 규칙 JSON의
`effect_definitions`를 올바른 형식으로 수정한 후 다시 열어야 합니다.

## 16. 데이터 파일 사용 시 주의사항

- JSON 파일을 외부 편집기로 수정하기 전 백업을 권장합니다.
- 모든 ID는 프로젝트 내에서 고유해야 합니다.
- ID는 영문 소문자 `snake_case`를 사용합니다.
- 색상은 `#RRGGBB` 형식을 사용합니다.
- 좌표는 정수여야 합니다.
- JSON에는 주석을 넣을 수 없습니다.
- `NaN`, `Infinity`, Python tuple 등은 사용할 수 없습니다.
- 게임 코드가 지원하지 않는 효과 ID를 추가해도 실제 게임에서는 동작하지
  않습니다.

예제 파일은 다음 위치에 있습니다.

```text
examples/blockable_rules.example.json
```
