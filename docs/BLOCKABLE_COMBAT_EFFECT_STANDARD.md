BLOCKABLE 공통 전투 효과 표준
버전: 1.0.0
대상: Blockable Block Designer, Blockable Monster Designer, Blockable 게임 런타임

===============================================================================
1. 목적
===============================================================================

이 문서는 Block Designer와 Monster Designer가 동일한 효과 ID, 상태 ID,
파라미터 이름과 대상·범위 규칙을 사용하도록 정의한다.

Designer가 출력하는 JSON과 Blockable 게임 파서는 이 문서를 공통 기준으로 삼는다.

기본 원칙:

1) 모든 ID는 영문 snake_case를 사용한다.
2) effect_id는 효과의 종류만 나타낸다.
3) target은 효과를 받는 진영 또는 기준 대상을 나타낸다.
4) range는 선택된 중심 슬롯에서 효과가 퍼지는 방식을 나타낸다.
5) 수치 크기는 amount, 개수는 count, 중첩은 stacks, 지속 턴은 duration을 사용한다.
6) 표시 이름과 설명은 effect_definitions 또는 status_definitions에서 관리한다.
7) 개별 효과 인스턴스에 한글 이름을 반복 저장하지 않는다.
8) 효과는 order 값이 낮은 순서부터 처리한다.
9) 알 수 없는 effect_id, status_id, target, range는 임의로 추정하지 않고 검증 오류로 처리한다.


===============================================================================
2. 공통 효과 객체 형식
===============================================================================

{
  "effect_id": "deal_damage",
  "order": 1,
  "parameters": {
    "target": "enemy",
    "range": "single",
    "distance": 0,
    "amount": 10
  }
}

공통 필드:

- effect_id
  - 타입: identifier/string
  - 필수: 예
  - 설명: 이 문서에서 정의한 효과 ID

- order
  - 타입: integer
  - 필수: 예
  - 최솟값: 0
  - 설명: 같은 능력 또는 조합 안에서의 효과 적용 순서

- parameters
  - 타입: object
  - 필수: 예
  - 설명: 효과별 파라미터


===============================================================================
3. 공통 대상 ID
===============================================================================

현재 확정 대상:

- self
  - 효과를 발생시킨 전투 개체 자신
  - 플레이어가 사용한 블록에서는 플레이어
  - 몬스터가 사용한 어빌리티에서는 해당 몬스터

- enemy
  - 효과 발생자의 적 진영에 있는 선택 대상
  - 플레이어가 사용한 블록에서는 선택한 몬스터
  - 몬스터가 사용한 어빌리티에서는 플레이어

향후 확장 예약 대상:

- ally
  - 효과 발생자와 같은 진영의 선택 대상 하나

- all_allies
  - 효과 발생자와 같은 진영의 모든 생존 대상

사용 중단 대상:

- player
  - Monster Designer에서 enemy와 같은 의미로 사용되던 값
  - 신규 데이터에서는 사용하지 않는다.
  - target: enemy로 변환한다.

- all_enemies
  - 과거 target 하나로 진영과 범위를 동시에 표현하던 값
  - 신규 데이터에서는 사용하지 않는다.
  - target: enemy, range: all로 변환한다.


===============================================================================
4. 공격 범위 ID
===============================================================================

범위 파라미터는 적 슬롯을 대상으로 하는 효과에 사용한다.

- single
  - 선택한 중심 슬롯 하나
  - distance는 생략하거나 0으로 설정한다.

- left
  - 중심 슬롯과 왼쪽 방향 슬롯
  - distance만큼 왼쪽으로 확장한다.

- right
  - 중심 슬롯과 오른쪽 방향 슬롯
  - distance만큼 오른쪽으로 확장한다.

- both
  - 중심 슬롯과 좌우 방향 슬롯
  - distance만큼 양쪽으로 확장한다.

- all
  - 적 진영의 모든 살아 있는 슬롯
  - distance를 사용하지 않는다.

distance:

- 타입: integer
- 최솟값: 0
- single에서는 0
- left, right, both에서는 1 이상
- all에서는 생략


===============================================================================
5. 전투 슬롯 범위 판정
===============================================================================

일반전 슬롯:

1 - 2 - 3 - 4

일반전에는 5번 슬롯이 없다.

보스전 슬롯:

1 -┐
2 -┤
3 -┼- 5
4 -┘

보스전에서 5번 보스 슬롯은 1~4번 슬롯 모두와 연결된다.

보스전 확정 예시:

- 중심 2 + left 1
  - 결과: 1, 2, 5

- 중심 2 + right 1
  - 결과: 2, 3, 5

- 중심 2 + both 1
  - 결과: 1, 2, 3, 5

- 중심 1 + left 1
  - 결과: 1, 5

- 중심 1 + right 1
  - 결과: 1, 2, 5

- 중심 5 + left 1
  - 결과: 1, 2, 3, 4, 5

- 중심 5 + right 1
  - 결과: 1, 2, 3, 4, 5

- 중심 5 + both 1
  - 결과: 1, 2, 3, 4, 5

추가 판정 규칙:

1) single 범위로 5번을 선택하면 5번만 대상이다.
2) 보스전에서 1~4번을 중심으로 left, right, both를 사용하면 살아 있는
   5번 보스도 범위에 포함된다.
3) 5번을 중심으로 left, right, both를 사용하면 살아 있는 1~4번과 5번이
   범위에 포함된다.
4) 빈 슬롯과 사망 슬롯은 최종 피격 대상에서 제외한다.
5) 사망한 몬스터의 슬롯 번호는 전투 종료까지 변경하지 않는다.
6) 화면 좌표가 아니라 슬롯 번호와 연결 규칙으로 판정한다.

6. 효과 ID 정의
===============================================================================

-------------------------------------------------------------------------------
6.1 deal_damage
-------------------------------------------------------------------------------

표시 이름:
피해

설명:
지정된 대상에게 amount만큼 피해를 가한다.
피해 대상의 방어도와 상태 효과 보정은 Blockable 전투 시스템이 처리한다.
range로 단일·방향·전체 공격을 표현한다.

필수 파라미터:

- target
  - 타입: enum
  - 허용값: self, enemy

- amount
  - 타입: number
  - 최솟값: 0
  - 설명: 대상 하나당 적용할 기본 피해량

조건부 필수 파라미터:

- range
  - 타입: enum
  - 허용값: single, left, right, both, all
  - target이 enemy이면 필수

- distance
  - 타입: integer
  - 최솟값: 1
  - range가 left, right, both이면 필수

단일 공격 예:

{
  "effect_id": "deal_damage",
  "order": 1,
  "parameters": {
    "target": "enemy",
    "range": "single",
    "amount": 10
  }
}

좌우 범위 공격 예:

{
  "effect_id": "deal_damage",
  "order": 1,
  "parameters": {
    "target": "enemy",
    "range": "both",
    "distance": 1,
    "amount": 15
  }
}

전체 공격 예:

{
  "effect_id": "deal_damage",
  "order": 1,
  "parameters": {
    "target": "enemy",
    "range": "all",
    "amount": 10
  }
}

자해 예:

{
  "effect_id": "deal_damage",
  "order": 1,
  "parameters": {
    "target": "self",
    "amount": 100
  }
}

6.2 gain_block
-------------------------------------------------------------------------------

표시 이름:
방어도 획득

설명:
대상의 현재 방어도에 amount를 더한다.
방어도는 체력 피해보다 먼저 피해를 흡수한다.

필수 파라미터:

- target
  - 타입: enum
  - 현재 허용값: self

- amount
  - 타입: integer
  - 최솟값: 0
  - 설명: 획득할 방어도 수치

예:

{
  "effect_id": "gain_block",
  "order": 1,
  "parameters": {
    "target": "self",
    "amount": 10
  }
}

사용 중단 파라미터:

- count
  - Block Designer에서 방어도 수치로 사용되던 이름
  - 신규 데이터에서는 amount를 사용한다.


-------------------------------------------------------------------------------
6.3 heal
-------------------------------------------------------------------------------

표시 이름:
회복

설명:
대상의 현재 체력을 amount만큼 회복한다.
현재 체력은 최대 체력을 초과할 수 없다.

필수 파라미터:

- target
  - 타입: enum
  - 현재 허용값: self

- amount
  - 타입: number
  - 최솟값: 0
  - 설명: 회복할 체력

예:

{
  "effect_id": "heal",
  "order": 1,
  "parameters": {
    "target": "self",
    "amount": 20
  }
}


-------------------------------------------------------------------------------
6.4 apply_status
-------------------------------------------------------------------------------

표시 이름:
상태 효과 적용

설명:
대상에게 status_id로 지정된 상태 효과를 stacks만큼 부여한다.
긍정 효과, 상태이상, 디버프와 군중 제어를 같은 효과 ID로 처리한다.

필수 파라미터:

- target
  - 타입: enum
  - 허용값: self, enemy

- status_id
  - 타입: identifier/string
  - 허용값: status_definitions에 존재하는 ID

- stacks
  - 타입: integer
  - 최솟값: 1

선택 파라미터:

- duration
  - 타입: integer 또는 null
  - 최솟값: 1
  - 설명: 스택과 별도로 지속 턴을 사용하는 상태에만 지정

적에게 화상 적용 예:

{
  "effect_id": "apply_status",
  "order": 1,
  "parameters": {
    "target": "enemy",
    "status_id": "burn",
    "stacks": 5
  }
}

자신에게 연속 공격 적용 예:

{
  "effect_id": "apply_status",
  "order": 1,
  "parameters": {
    "target": "self",
    "status_id": "double_attack",
    "stacks": 1
  }
}

사용 중단 필드:

- status_name
  - 개별 효과에 한글 이름을 반복하지 않는다.
  - status_definitions의 display_name을 사용한다.

6.7 modify_next_effect
-------------------------------------------------------------------------------

표시 이름:
다음 효과 변경

설명:
다음에 적용할 수치 효과를 multiplier만큼 변경하기 위한 예약 효과다.
현재 Blockable 런타임에서 최종 적용 규칙이 확정되지 않았으므로
Designer는 신규 콘텐츠에 이 효과를 출력하지 않는다.

필수 파라미터:

- multiplier
  - 타입: number
  - 최솟값: 0

미확정 항목:

- 다음 효과 하나에만 적용할지 여부
- 피해, 회복, 방어도 중 어떤 효과에 적용할지
- 중첩 가능 여부
- 적용 후 소비 시점

상태:

- reserved
- Designer 생성 비활성 권장

7.1 bleeding
-------------------------------------------------------------------------------

표시 이름:
출혈

분류:
상태이상 / 지속 피해

설명:
플레이어 기준 턴 종료 시 이번 턴에 배치한 블록 수 × 출혈 스택만큼
방어도를 무시하는 피해를 받는다. 처리 후 스택이 1 감소한다.

권장 ID:
bleeding

사용 중단 alias:
bleed

7.2 burn
-------------------------------------------------------------------------------

표시 이름:
화상

분류:

현재 규칙에서는 방어도로 흡수할 수 있으며 처리 후 스택이 절반으로 감소한다.

권장 ID:
burn

===============================================================================
8. apply_buff 처리 방침
===============================================================================

apply_buff는 apply_status와 의미가 중복되므로 신규 공통 표준에서 사용하지 않는다.

기존:

{
  "effect_id": "apply_buff",
  "parameters": {
    "buff_id": "doubleAttack",
    "amount": 1
  }
}

권장:

{
  "effect_id": "apply_status",
  "parameters": {
    "target": "self",
    "status_id": "double_attack",
    "stacks": 1
  }
}

Designer UI에서는 상태 분류(category)가 buff인 항목을 선택하더라도
출력 effect_id는 apply_status로 통일한다.


===============================================================================
9. 기존 데이터 변환표
===============================================================================

효과·파라미터 변환:

- gain_block.parameters.count
  -> gain_block.parameters.amount

- deal_damage.parameters.target = player
  -> deal_damage.parameters.target = enemy

- deal_damage.parameters.target = all_enemies
  -> deal_damage.parameters.target = enemy
  -> deal_damage.parameters.range = all

- target이 없는 플레이어 자기 효과
  -> target = self 추가

- apply_buff
  -> apply_status

- buff_id
  -> status_id

- buff의 amount
  -> stacks

상태 ID 변환:

- bleed
  -> bleeding

- weak
  -> weakness

- injury
  -> wound

- injry
  -> wound

- doubleAttack
  -> double_attack


===============================================================================
10. Designer 검증 규칙
===============================================================================

공통:

1) effect_id는 effect_definitions에 존재해야 한다.
2) status_id는 status_definitions에 존재해야 한다.
3) order는 0 이상의 정수여야 한다.
4) 필수 파라미터가 누락되면 저장 또는 export를 차단한다.
5) 정의되지 않은 추가 파라미터는 경고가 아니라 오류로 처리한다.
6) deprecated alias는 신규 생성할 수 없고 import 시 표준 ID로 변환한다.

피해:

1) target = enemy이면 range가 필수다.
2) range = left, right, both이면 distance가 필수다.
3) range = single이면 distance는 생략하거나 0이어야 한다.
4) range = all이면 distance를 출력하지 않는다.
5) amount는 대상마다 적용할 피해량이다.

상태:

1) stacks는 1 이상의 정수다.
2) stun은 export 시 stacks를 1로 제한한다.
3) 개별 효과에 status_name을 저장하지 않는다.
4) 긍정 효과도 apply_status를 사용한다.

13. 구현 상태 주의사항
===============================================================================

이 문서는 Designer 출력의 목표 표준이다.
현재 Blockable 게임 런타임에는 기존 JSON과의 호환을 위한 adapter가 일부 존재하며,
다음 항목은 표준 JSON 적용과 함께 런타임 보완이 필요하다.

- 몬스터에게 적용된 화상·출혈의 턴 종료 처리
- 다중 몬스터 행동 대기열에서 기절에 의한 행동 취소
- doubleAttack을 double_attack으로 변경
- gain_block의 count를 amount로 변경
- Monster Designer의 player 대상을 enemy로 변경
- 기존 all_enemies를 range = all로 변경
- left, right, both, distance를 JSON 효과와 슬롯 판정 시스템에 연결
- modify_next_effect의 실제 적용 규칙 확정
