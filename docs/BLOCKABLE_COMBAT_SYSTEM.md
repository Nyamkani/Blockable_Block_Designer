이 문서는 Blockable의 전투 시스템을 실제 게임에 구현하기 위한 상세 명세이다.

전체 게임의 방향과 콘텐츠 구성은 `BLOCKABLE_GAME_DESIGN_V0.5.2.md`에서 관리하고, 이 문서에서는 다음 내용을 구체적으로 정의한다.

- 전투의 시작부터 종료까지의 진행 순서
- 블록 배치, 색상 효과, 조합 및 콤보 처리
- 피해와 상태 효과의 적용 순서

- 전투 데이터와 런타임 상태의 분리
- 구현 단계와 검증 시나리오

개별 몬스터의 능력과 행동 패턴은 이 문서에 중복 기재하지 않는다. 해당 정보의 단일 기준은 Blockable Monster Designer가 생성한 JSON 데이터이다.

## 3. 전투의 핵심 구조

Blockable의 전투는 플레이어가 블록을 배치하고, 블록의 공격력·색상·효과·조합 결과를 이용해 몬스터를 공격하는 턴 기반 전투이다.

전투의 핵심 선택은 다음 세 가지이다.

- 어떤 블록을 어떤 위치에 배치할 것인가
- 어떤 몬스터를 직접 공격 대상으로 지정할 것인가
- 블록의 개별 효과와 콤보 효과를 어떤 순서로 활용할 것인가

몬스터는 Monster Designer에서 지정된 행동 패턴에 따라 행동한다. 전투 엔진은 몬스터별 패턴을 직접 코드에 작성하지 않고, JSON 데이터를 해석하여 이번 행동을 결정하고 실행한다.

## 4. 전투 구성 요소

### 4.1 플레이어

전투에서 사용하는 플레이어 정보는 최소한 다음 항목을 포함한다.

- 현재 HP / 최대 HP
- ATK
- DEF
- 버프 목록
- 디버프 목록
- 골드
- 현재 턴에 남은 블록 배치 횟수
- 보유 블록 또는 사용 가능한 블록 목록
- 전투 중 획득하거나 소비하는 자원

추가 자원의 종류와 최대 보유량은 별도 기획에서 확정한다.

### 4.2 블록

블록은 최소한 다음 속성을 가진다.

- ID
- 이름
- 등급 또는 분류
- 기본 블록 / 고유 블록 구분
- 형태
- 색상
- 기본 공격력
- 개별 효과
- 조합 조건
- 조합 효과
- 공격 범위 또는 대상 규칙

기본 색상은 다음 7종을 사용하며, 향후 확장할 수 있다.

- 빨강
- 주황
- 노랑
- 초록
- 파랑
- 남색
- 보라

색상별 구체 효과와 색상 간 조합표는 Block Designer 데이터 또는 별도 블록 규칙 문서에서 관리한다.

### 4.3 몬스터

몬스터는 최소한 다음 정보를 가진다.

- ID
- 이름
- 등급 또는 티어
- 현재 HP / 최대 HP
- ATK
- DEF
- 버프 목록
- 디버프 목록
- 능력 목록
- 행동 패턴
- 현재 행동 패턴 위치
- 현재 페이즈
- 다음 행동 의도
- 전투 슬롯 번호
- 생존 상태
- 이미지 리소스

## 5. 전투 전체 흐름

전투는 다음 단계로 진행한다.

### 5.1 전투 초기화

1. 전투 종류를 결정한다.
   - 일반 전투
   - 보스전
2. 출전 몬스터와 슬롯을 생성한다.
3. 플레이어와 몬스터의 전투 시작 상태를 초기화한다.
4. 각 몬스터의 행동 패턴과 최초 페이즈를 초기화한다.
5. 각 몬스터의 다음 행동을 미리 계산한다.
6. 다음 행동 아이콘과 공격 대상 정보를 UI에 표시한다.
7. 기본 공격 대상을 선택한다.
8. 플레이어 턴을 시작한다.

### 5.2 플레이어 턴

1. 턴 시작 효과를 처리한다.
2. 사용 가능한 블록과 남은 배치 횟수를 표시한다.
3. 플레이어가 공격 대상 몬스터를 선택한다.
4. 플레이어가 블록을 배치한다.
5. 배치 결과에 따라 개별 효과와 조합 가능성을 갱신한다.
6. 공격 범위에 포함되는 몬스터 슬롯을 미리 강조한다.
7. 플레이어가 행동을 확정한다.
8. 기본 공격을 `H`회 개별 실행하고, 남은 기본 공격 처리가 끝난 뒤 `A` 독립 공격을 별도 실행한다.
9. `S` 자신 버프와 `C` 상대 디버프를 정해진 시점에 갱신한다.
10. 사망한 몬스터와 사망·연쇄 효과 대기열을 처리한다.
11. 보스전에서 보스가 사망했다면 즉시 승리하고 남은 처리를 취소한다.
12. 일반전에서는 대기열이 빈 뒤 전투의 계속 여부를 검사한다.
13. 추가 턴 발생 여부를 기록한다.
14. 추가 턴이 없으면 몬스터 행동 단계로 이동한다.
15. 추가 턴이 있으면 몬스터 행동을 건너뛰고 턴 종료 단계로 이동한다.

### 5.3 몬스터 행동 단계

1. 행동 가능한 살아 있는 몬스터 목록을 만든다.
2. 정해진 행동 순서에 따라 몬스터 행동을 대기열에 넣는다.
3. 각 몬스터의 예약된 능력을 순서대로 실행한다.
4. 행동 중인 몬스터를 대형 이미지 영역에 표시한다.
5. 능력 효과를 `order` 순서에 따라 적용한다.
6. 각 행동 뒤 사망·연쇄 효과 대기열을 비운다.
7. 플레이어 사망 또는 보스 사망 여부를 검사한다.
8. 정상 행동 또는 기절로 건너뛴 몬스터의 행동 패턴 위치를 진행한다.
9. 모든 몬스터 행동이 끝나면 턴 종료 상태이상 단계로 이동한다.

### 5.4 턴 종료 단계

1. 플레이어의 출혈과 화상 피해 및 각 상태의 스택 감소를 정해진 순서로 처리한다.
2. 살아 있는 몬스터의 출혈과 화상 피해 및 각 상태의 스택 감소를 1번부터 5번 슬롯 순서로 처리한다.
3. 각 상태이상 피해 묶음 뒤 사망·연쇄 효과 대기열을 처리한다.
4. 약화와 상처의 감소 조건을 판정하고 해당 스택을 감소시킨다.
5. 전투 종료 조건을 최종 검사한다.
6. 전투가 계속되면 방어도, 퍼즐 판과 턴 한정 상태를 정리한다.
7. 추가 턴이 예약되어 있으면 지정된 블록 리필 규칙으로 추가 턴을 시작한다.
8. 추가 턴이 없으면 다음 일반 턴의 행동 의도를 계산하고 플레이어 턴을 시작한다.

### 5.5 전투 종료

- 승리 조건을 만족하면 보상 처리 단계로 이동한다.
- 플레이어 HP가 0 이하가 되면 패배 처리 단계로 이동한다.
- 일반전은 현재 효과와 모든 사망·연쇄 효과를 처리한 뒤 모든 적이 사망하고 플레이어가 살아 있을 때 승리한다.
- 보스전은 5번 보스의 사망이 확정되는 즉시 승리하며 남은 부하, 행동 대기열, 상태이상 처리와 미실행 효과를 취소한다.
- 전투가 종료된 이후에는 남아 있는 행동, 애니메이션, 지연 콜백이 피해나 상태 변화를 발생시킬 수 없다.

## 6. 턴의 효과 적용 순서

### 6.1 한 전투 턴의 처리 순서

현재 확정된 한 전투 턴의 처리 순서는 다음과 같다.

1. 플레이어가 블록 배치를 확정한다.
2. 블록 자체 효과, 조합, 조건부 효과와 색상 시너지를 판정한다.
3. 기본 공격을 `H`회 개별 실행한다.
4. 기본 공격의 모든 처리가 끝난 뒤 `A` 독립 공격을 자체 타겟팅으로 실행한다.
5. `S` 자신 버프와 `C` 상대 디버프를 정해진 시점에 갱신한다.
6. 사망자와 사망·연쇄 효과 대기열을 처리한다.
7. 보스전이면 보스 즉시 승리 예외를 검사한다.
8. 추가 턴 발생 여부를 기록한다.
9. 추가 턴이 없으면 살아 있는 몬스터가 슬롯 순서대로 행동한다.
10. 몬스터 행동마다 기절과 생존 상태를 검사하고, 행동 뒤 사망·연쇄 효과 대기열을 처리한다.
11. 턴 종료 단계에서 플레이어와 살아 있는 몬스터의 출혈·화상을 처리한다.
12. 턴 종료 감소 대상인 약화·상처 스택을 감소시킨다.
13. 전투 종료를 최종 판정하고 턴 한정 상태를 정리한다.
14. 추가 턴 또는 다음 일반 턴을 시작한다.

상태이상 피해는 플레이어 공격 전이나 몬스터 행동 전에 처리하지 않는다. 출혈과 화상은 한 전투 턴의 행동 단계가 끝난 뒤 `TURN_END_STATUS_DAMAGE` 단계에서 처리한다.

### 6.2 플레이어 행동의 공격 공식

플레이어 행동의 수치 피해는 기본 공격과 `A` 독립 공격을 하나의 총합식으로 합치지 않고 별도로 계산하고 실행한다.

```text
기본 공격 1타 피해량 = (B + P) × M × D × W
→ H회 개별 공격

A 독립 공격 피해량 = A × M × D × W
→ 기본 공격의 모든 처리가 끝난 뒤 별도 실행

상태 갱신 = S, C
→ 공격 처리 뒤 정해진 시점에 각각 적용
```

| 기호 | 이름 | 계산 기준 |
|---|---|---|
| `B` | 기초 공격력 | 이번 기본 공격에 참여한 단일 블록들이 제공하는 공격력의 합 |
| `P` | 버프 데미지 추가 값 | 공격자가 현재 보유한 버프 스택으로부터 계산된 데미지 추가 값의 합 |
| `H` | 기본 공격 횟수 | 기본값과 공격 횟수 증감치를 합산한 개별 기본 공격 실행 횟수 |
| `A` | 독립 공격 기준값 | 조합·시너지 등으로 발생하며 기본 공격 뒤 별도 실행되는 공격의 피해 기준값 |
| `M` | 공격력 배율 | 공격자에게 적용된 공격력 배율 버프들을 서로 곱한 계수 |
| `D` | 공격력 감쇄 계수 | 공격자에게 걸린 약화 등 공격력 감쇄율을 합산해 만든 계수 |
| `W` | 받는 피해 증가 계수 | 실제 공격 대상에게 걸린 상처 등 받는 피해 증가율을 합산해 만든 계수 |
| `S` | 자신 상태 갱신 | 자신에게 적용할 버프의 ID, 스택과 적용 시점 |
| `C` | 상대 상태 갱신 | 상대에게 적용할 디버프의 ID, 스택과 적용 시점 |

세부 계산 규칙:

```text
P = Σ(currentBuffDamageBonuses)

H = baseHitCount
  + Σ(currentActionBaseHitCountValues)
  + Σ(hitCountModifiers)

M = Π(attackerAttackMultipliers)

D = max(0, 1 - Σ(attackerAttackReductionRates))

W = 1 + Σ(actualTargetDamageTakenIncreaseRates)
```

- 분노 1스택은 현재 버프로부터 계산되는 `P`에 데미지 추가 값 `1`을 제공한다.
- `P`는 버프 ID나 스택 그 자체가 아니라, 현재 버프로부터 이미 계산된 데미지 추가 수치다.
- `currentActionBaseHitCountValues`는 이번 행동에 포함된 `BASE_HIT_COUNT.value`의 합이다.
- `BASE_HIT_COUNT`는 이번 행동의 `H`를 즉시 변경하며, 공격 후 `S`에 등록되어 이후 행동부터 적용되는 `BUFF + HIT_COUNT`와 구분한다.
- 기본 공격은 1타 피해량을 `H`회 개별 실행한다. 각 타격마다 방어도, 체력, 반응, 사망과 연쇄 효과를 처리한다.
- `A`는 `H`에 포함되는 추가 타격이나 추가 턴 피해가 아니다.
- `A`는 기본 공격의 모든 타격과 그에 따른 처리가 끝난 뒤 실행하는 독립적인 공격이다.
- 기본 공격 대상이 사망해 남은 연타가 종료되어도 `A`는 자동 취소되지 않으며, `A` 자체의 타겟팅 영역과 범위로 유효성을 판정한다.
- `M`은 공격자에게 걸린 공격력 배율 버프의 곱이다.
- `D`는 공격자에게 걸린 디버프의 공격력 감쇄율 합을 `1`에서 뺀 계수다.
- `W`는 각 공격이 실제로 적중할 대상의 현재 상처 상태를 기준으로 계산한다.
- 범위 공격은 `B`, `P`, `M`, `D`를 공유할 수 있지만 `W`와 방어도는 대상별 현재 상태로 계산한다.
- `S`와 `C`는 피해량에 더하지 않는다. 공격 뒤 별도의 상태 갱신 데이터로 처리하며, 세부 적용 시점은 추가 버프 설계에서 확정한다.
- 상태이상 피해, 사망 효과 피해와 Monster Designer 능력 피해가 이 공식을 사용할지는 해당 효과 데이터가 명시한다. 출혈과 화상에는 이 공식을 적용하지 않는다.

예:

```text
B = 10
P = 3
H = 2
A = 5
M = 1.5
약화 2스택 → D = 0.8
대상 상처 1스택 → W = 1.1

기본 공격 1타 = (10 + 3) × 1.5 × 0.8 × 1.1
                 = 17.16
→ 최대 2회 개별 실행

A 독립 공격 = 5 × 1.5 × 0.8 × 1.1
             = 6.6
→ A 자체의 대상과 범위에 별도 실행
```

### 6.3 방어도와 체력 적용

방어도는 피해를 고정 수치만큼 대신 받는 소모형 수치다. 방어도 증가율 또는 방어도 배율은 현재 전투 시스템에 존재하지 않는다.

```text
armorDamage = min(currentArmor, damage)
hpDamage = max(0, damage - currentArmor)

nextArmor = max(0, currentArmor - damage)
nextHp = max(0, currentHp - hpDamage)
```

- 각 기본 공격과 `A` 독립 공격의 `damage`는 대상의 현재 방어도에 먼저 적용한다.
- 방어도를 초과한 피해만 체력에 적용한다.
- 철갑은 1스택당 방어도 `+1`을 제공한다.
- 방어도 증가는 모두 고정값 합연산으로 처리한다.
- 방어도 무시 피해는 방어도를 변경하지 않고 체력에 직접 적용한다.
- 개념적으로 `현재 체력 + 현재 방어도 - damage`로 총 생존 수치 변화를 볼 수 있지만, 실제 상태 갱신은 방어도와 체력을 위 공식처럼 분리한다.
- 피해 적용 후 체력이 `0`이면 사망 처리한다.

### 6.4 상태이상 분류와 적용 시점

| 분류 | 상태 | 적용 시점 |
|---|---|---|
| 피해 계산 디버프 | 약화 | 공격자가 일반 피해를 계산할 때 `D`에 반영 |
| 피해 계산 디버프 | 상처 | 대상이 일반 피해를 받을 때 `W`에 반영 |
| 군중 제어 | 기절 | 몬스터의 예약 행동 실행 직전 |
| 턴 종료 피해 | 출혈 | `TURN_END_STATUS_DAMAGE` |
| 턴 종료 피해 | 화상 | `TURN_END_STATUS_DAMAGE` |

#### 약화

```text
공격력 감쇄율 합계 = 약화 스택 × 0.10
D = max(0, 1 - 공격력 감쇄율 합계)
```

- 약화 1스택당 공격자의 일반 공격 피해를 `10%` 감소시킨다.
- 약화는 기본 공격과 `A` 독립 공격의 최종 곱연산 단계인 `D`에 적용한다.
- 턴 종료 시 감소 자격이 있는 약화 스택을 `1` 감소시킨다.

#### 상처

```text
받는 피해 증가율 합계 = 상처 스택 × 0.10
W = 1 + 받는 피해 증가율 합계
```

- 상처 1스택당 대상이 받는 일반 피해를 `10%` 증가시킨다.
- 상처는 공격자 상태가 아니라 피해를 받는 대상의 상태로 계산한다.
- 턴 종료 시 감소 자격이 있는 상처 스택을 `1` 감소시킨다.
- 출혈과 화상은 상태이상 자체 수치로 피해가 확정되므로 상처의 `W`를 적용하지 않는다.

#### 약화·상처의 감소 자격

새로 부여된 약화·상처가 효과를 발휘하기도 전에 사라지는 것을 막기 위해 스택의 적용 턴과 피해 계산 참여 여부를 추적한다.

- 이전 턴부터 존재한 스택은 턴 종료 감소 대상이다.
- 현재 턴에 새로 부여된 스택은 해당 턴의 피해 계산에 한 번 이상 실제로 참여했을 때만 감소 대상이다.
- 현재 턴에 부여되었지만 아직 적용 기회가 없었던 스택은 다음 턴까지 유지한다.
- 기존 스택과 새 스택이 섞이면 새로 부여된 부분의 감소 자격을 별도로 기록한다.

권장 런타임 정보:

```text
appliedTurnId
appliedStackCount
hasAffectedDamageCalculation
```

#### 기절

- 기절은 최대 `1`스택이며 중첩되지 않는다.
- 예약된 몬스터 행동을 실행하기 직전에 기절 여부를 검사한다.
- 기절 상태이면 현재 예약 행동의 효과를 실행하지 않고 해당 행동 턴을 건너뛴다.
- 행동을 실제로 건너뛴 직후 기절 스택을 제거한다.
- 기절로 취소된 능력의 효과와 신규 쿨다운은 적용하지 않는다.
- 기절로 행동을 건너뛰어도 몬스터의 행동 패턴 위치는 다음 단계로 진행한다.
- 몬스터가 행동 차례 전에 사망했다면 행동과 기절 소비를 모두 수행하지 않는다.

#### 출혈

```text
bleedDamage = placedBlockCountThisTurn × bleedStacks
```

- `placedBlockCountThisTurn`은 턴 종료 시 판에 남은 수가 아니라 이번 턴에 최종 확정해 사용한 블록 수다.
- 출혈 피해는 방어도를 무시하고 체력에 직접 적용한다.
- 이번 턴에 새로 부여된 출혈도 같은 턴 종료에 피해를 발생시킨다.
- 피해 계산에는 감소 전 출혈 스택을 사용한다.
- 피해 처리 후 출혈 스택을 `1` 감소시킨다.

#### 화상

```text
burnDamage = burnStacks
nextBurnStacks = floor(burnStacks / 2)
```

- 화상 피해는 방어도로 막을 수 있다.
- 이번 턴에 새로 부여된 화상도 같은 턴 종료에 피해를 발생시킨다.
- 피해 계산에는 감소 전 화상 스택을 사용한다.
- 피해 처리 후 화상 스택을 절반으로 감소시키며 홀수는 내림한다.

### 6.5 턴 종료 상태이상 해결 순서

턴 종료 상태이상은 다음 순서로 해결한다.

1. 플레이어 출혈 피해 적용
2. 플레이어 출혈 스택 감소
3. 사망 및 패배 판정
4. 플레이어가 살아 있으면 화상 피해 적용
5. 플레이어 화상 스택 감소
6. 사망 및 패배 판정
7. 플레이어 약화·상처 감소 자격 판정 및 감소
8. 살아 있는 몬스터를 1번부터 5번 슬롯 순서로 선택
9. 해당 몬스터의 출혈 피해 적용 및 출혈 스택 감소
10. 사망 및 사망·연쇄 효과 대기열 처리
11. 생존했다면 화상 피해 적용 및 화상 스택 감소
12. 사망 및 사망·연쇄 효과 대기열 처리
13. 생존했다면 약화·상처 감소 자격 판정 및 감소
14. 다음 살아 있는 슬롯으로 반복
15. 일반전 최종 승리·패배 판정

추가 규칙:

- 출혈을 화상보다 먼저 처리한다.
- 하나의 상태이상 피해로 객체가 사망하면 그 객체의 남은 상태이상 처리를 중단한다.
- 상태이상 피해로 발생한 사망 효과는 일반 사망·연쇄 효과 대기열에 등록한다.
- 보스전에서 상태이상 피해로 5번 보스가 사망하면 즉시 승리하고 남은 상태이상 및 연쇄 처리를 취소한다.
- 전투가 종료된 뒤에는 스택 감소와 후속 상태이상 피해를 더 처리하지 않는다.

### 6.6 계산 및 로그 규칙

- 각 항목의 덧셈·곱셈 순서를 임의로 변경하지 않는다.
- 소수점 처리 방식은 아직 미확정이다.
- 최소 피해 보장 여부는 아직 미확정이다.
- 치명타를 추가한다면 최종 배율 단계 또는 별도 단계로 정의해야 한다.
- 전투 계산기는 다음 중간값과 상태이상 처리 근거를 로그로 남길 수 있어야 한다.

```text
B, P, H
baseAttackDamagePerHit
A, independentAttackDamage
M, D, W
S, C
currentArmor
armorDamage
hpDamage
placedBlockCountThisTurn
bleedStacksBefore / bleedDamage / bleedStacksAfter
burnStacksBefore / burnDamage / burnStacksAfter
statusAppliedTurnId
statusDecayEligible
```

### 6.7 플레이어 행동 내부 처리 순서

```text
플레이어 행동 시작

1. 기본 공격
   1타 피해량 = (B + P) × M × D × W
   → H회 개별 공격
   → 대상 사망·무효화 시 남은 연타와 해당 공격 기회 종료
   → 다른 적에게 재지정하지 않음

2. A 독립 공격
   피해량 = A × M × D × W
   → 기본 공격의 모든 처리가 끝난 뒤 별도로 실행
   → A 자체의 타겟팅 영역과 범위로 판정

3. 상태 갱신
   → S: 자신에게 버프 적용
   → C: 상대에게 디버프 적용

플레이어 행동 종료
```

### 6.8 대상 사망 또는 무효화 시 재지정 규칙

- 기본 공격의 중심 대상이 사망하거나 유효하지 않게 되면 다른 적으로 재지정하지 않는다.
- 무효화된 시점에서 해당 기본 공격 기회의 남은 연타와 후속 처리를 종료한다.
- 이 규칙은 연타 도중뿐 아니라 추가 턴에서 실행되는 공격 기회에도 동일하게 적용한다.
- 최초 중심 대상이 무효화되어 공격 기회가 종료되면, 그 공격 기회에 포함된 후속 효과가 범위 공격이어도 실행하지 않는다.
- 범위 공격이 유효하게 시작된 뒤 중심 대상이 아닌 범위 내 대상 하나가 사망한 경우, 이미 확정된 다른 유효 대상의 처리는 계속할 수 있다.
- 중심 대상 없이 실행하는 `ALL` 효과는 실행 시점의 살아 있는 대상을 기준으로 판정한다.
- `A`는 기본 공격과 독립된 공격이므로 기본 공격 대상의 사망으로 자동 취소되지 않는다. 기본 공격 처리가 끝난 뒤 `A` 자체의 타겟팅 규칙으로 다시 판정한다.
- `A` 자체의 지정 대상이 사망하거나 무효화되었다면 `A` 역시 다른 적에게 재지정하지 않고 종료한다.
- 새 대상을 선택할 수 있는 별도의 새 행동이 시작되기 전까지 남은 피해를 다른 적에게 이전하지 않는다.

## 7. 블록 배치와 콤보

### 7.1 기본 규칙

- 플레이어는 정해진 횟수만큼 블록을 배치한다.
- UI에는 `현재 남은 배치 수 / 최대 배치 수`를 표시한다.
- 블록은 형태와 배치 위치에 따라 다른 블록과 연결되거나 조합된다.
- 블록의 색상은 개별 특수 효과를 발생시킬 수 있다.
- 조합 조건을 충족하면 콤보 공격 또는 추가 효과가 발생한다.

### 7.2 동일 색상 보너스

하나의 콤보를 구성하는 모든 블록이 같은 색상이라면 일반 콤보 효과에 추가 효과가 발생한다.

```text
조합 성립
→ 기본 콤보 효과 적용
→ 모든 조합 블록의 색상 동일 여부 검사
→ 동일하면 색상 추가 효과 적용
```

동일 색상 추가 효과의 실제 수치와 종류는 블록 데이터에서 정의한다.

### 7.3 블록 실행 순서

하나의 행동에 여러 블록과 효과가 포함될 경우 다음 구조를 권장한다.

1. 배치 확정
2. 조합 그룹 계산
3. 직접 대상과 범위 대상 계산
4. 블록 개별 선행 효과
5. `B`, `P`, `H` 확정
6. `M`, `D` 확정
7. 대상별 `W` 확정
8. `(B + P) × M × D × W`를 H회 개별 실행
9. 각 기본 공격 뒤 대상별 방어도·체력·사망·연쇄 효과 처리
10. `A × M × D × W` 독립 공격의 대상과 범위 확정 및 실행
11. `S` 자신 버프와 `C` 상대 디버프 갱신
12. 남은 사망·연쇄 효과 대기열 처리
13. 일반전 종료 조건 또는 보스전 즉시 종료 예외 판정

개별 블록 데이터에 명시적인 실행 순서가 존재한다면 해당 순서를 우선하되, 전투 종료 판정은 각 피해 묶음 이후 안전하게 실행한다.

### 7.4 공통 효과 데이터 구조

모든 전투 효과는 `effect_id`, `effect_name`, `description`, `target`, `value`,
`type`, `parameters`의 공통 구조로 관리한다. `target`은 자신·좌·우·선택
대상·전체 등 적용 대상을, `value`는 피해·방어·회복·스택 또는 자원 증감
수치를 나타낸다. `type`은 효과의 실제 실행 방식을 결정한다.

권장 `type`:

```text
BASE_DAMAGE
BASE_HIT_COUNT
INDEPENDENT_DAMAGE
BLOCK
RECOVERY
STATUS_DAMAGE
DEBUFF
CROWD_CONTROL
BUFF
EXTRA_TURN
DECK_CAPACITY
DRAW
PLACEMENT_COUNT
```

- `BASE_DAMAGE`는 `B`와 `P`를 사용하는 기본 공격이다.
- `BASE_HIT_COUNT`는 이번 행동의 기본 공격 횟수 `H`에 `value`를 즉시 합산한다.
  이 효과는 상태로 저장하지 않으며 `parameters.id`는 `CURRENT_ACTION`,
  `duration`과 `intensify`는 `0`을 사용한다.
- `INDEPENDENT_DAMAGE`는 `A`를 사용하는 독립 공격이다.
- `EXTRA_TURN`은 현재 행동 처리가 끝난 뒤 추가 턴을 예약한다.
- `DECK_CAPACITY`, `DRAW`, `PLACEMENT_COUNT`는 각각 덱 한도, 드로우 수, 턴 배치 횟수를 증감한다.
- 특정 블록을 덱에 추가하는 효과는 숫자 `value`와 별도로
  `parameters.id`에 해당 블록 ID를 기록한다. `reference_id`는 사용하지 않는다.

`H`의 생성 규칙은 다음과 같다.

```text
H = baseHitCount
  + Σ(BASE_HIT_COUNT.value)
  + Σ(기존 BUFF + HIT_COUNT 상태의 공격 횟수 증감치)
```

`BASE_HIT_COUNT`와 `BUFF + HIT_COUNT`는 적용 시점이 다르다.

- `BASE_HIT_COUNT`: 조합·시너지 등 이번 행동의 연타 횟수를 공격 실행 전에 즉시
  변경한다.
- `BUFF + HIT_COUNT`: `S` 자신 상태 갱신에 등록하며, 상태가 실제로 반영된 이후
  행동부터 `H` 계산에 참여한다.

예:

```json
{
  "effect_id": "current_action_hit_count_up_01",
  "effect_name": "이번 행동 연타 증가",
  "description": "이번 행동의 기본 공격 횟수를 1회 증가시킨다.",
  "target": "self",
  "value": 1,
  "type": "BASE_HIT_COUNT",
  "parameters": {
    "id": "CURRENT_ACTION",
    "duration": 0,
    "intensify": 0
  }
}
```

## 8. 몬스터 전투 슬롯

### 8.1 슬롯 구성

전투에는 최대 5개의 몬스터 슬롯을 사용한다.

| 슬롯 | 용도 |
|---:|---|
| 1 | 일반 몬스터 또는 보스 부하 |
| 2 | 일반 몬스터 또는 보스 부하 |
| 3 | 일반 몬스터 또는 보스 부하 |
| 4 | 일반 몬스터 또는 보스 부하 |
| 5 | 보스 전용 |

일반 전투에서는 1~4번 슬롯만 사용한다. 보스전에서는 1~4번 부하 슬롯과 5번 보스 슬롯을 사용할 수 있다.

### 8.2 일반 전투 배치

1~4번 슬롯은 전투 화면 오른쪽에 왼쪽 위에서 오른쪽 아래로 내려가는 대각선 형태로 배치한다.

```text
[1]
      [2]
            [3]
                  [4]
```

이는 시각적 배치이며, 공격 범위 판정은 화면 좌표가 아니라 슬롯 연결 규칙을 사용한다.

### 8.3 보스전 배치

보스전에서는 1~4번 슬롯 뒤에 5번 보스 전용 영역을 둔다. 5번 슬롯은 1~4번보다 크며, 네 부하 슬롯과 연결된 중심 또는 후방 영역처럼 표현한다.

```text
[1] ─┐
[2] ─┼─ [5: 보스]
[3] ─┼─
[4] ─┘
```

연결선은 항상 강하게 표시하지 않는다.

- 기본 상태에서는 바닥 문양이나 약한 프레임으로 연결감을 표현한다.
- 범위 공격을 미리 볼 때 영향받는 슬롯과 연결선만 강조한다.
- 5번 보스는 직접 클릭하여 공격 대상으로 지정할 수 있다.
- 보스 HP는 일반 슬롯보다 큰 전용 HP 바로 표시한다.

### 8.4 빈 슬롯과 사망 슬롯

- 몬스터가 없는 슬롯은 비활성 슬롯으로 유지한다.
- 몬스터가 사망해도 다른 몬스터의 슬롯 번호를 앞으로 당기지 않는다.
- 사망한 슬롯은 해당 전투가 끝날 때까지 빈자리로 유지한다.
- 이 규칙은 공격 범위와 연결 판정이 턴 도중 바뀌는 것을 방지한다.

## 9. 대상 선택과 공격 범위 표시

### 9.1 직접 대상 선택

플레이어가 소형 몬스터 슬롯을 클릭하면 다음 처리를 수행한다.

1. 해당 몬스터를 현재 직접 대상으로 지정한다.
2. 슬롯에 강한 선택 테두리를 표시한다.
3. 대형 이미지 영역을 선택된 몬스터로 변경한다.
4. 몬스터의 이름, HP, DEF, 상태 효과와 다음 행동을 표시한다.
5. 현재 블록 또는 조합이 공격할 다른 슬롯을 계산한다.
6. 범위 대상 슬롯을 별도 색상으로 강조한다.

### 9.2 강조 단계

| 구분 | 표시 |
|---|---|
| 직접 대상 | 강한 붉은색 또는 주요 선택 테두리 |
| 범위 대상 | 주황색 또는 보조 범위 테두리 |
| 선택 불가 | 어둡게 표시 |
| 사망 | 비활성화, 처치 표시 |
| 현재 행동 중 | 행동 전용 점등 또는 프레임 |

색상은 전체 UI 팔레트와 접근성을 고려해 최종 조정한다. 색상만으로 상태를 구분하지 않고 테두리 모양, 아이콘 또는 밝기 차이를 함께 사용한다.

### 9.3 범위 계산 원칙

- 범위는 슬롯 번호와 연결 관계를 기준으로 계산한다.
- 시각적 좌표를 이용해 충돌 판정하지 않는다.
- 공격을 확정하기 전에 모든 피격 예정 슬롯을 표시한다.
- 사망 또는 빈 슬롯은 공격 대상에서 제외한다.
- 범위가 빈 슬롯을 지나 다음 슬롯까지 전달되는지는 블록 효과의 정의를 따른다.
- 5번 보스와 1~4번 슬롯의 구체적인 인접 규칙은 공격 범위 명세에서 고정해야 한다.

### 9.4 범위 규칙 미확정 항목

다음은 별도 확정이 필요하다.

- 1~4번 슬롯의 정확한 인접 관계
- `좌 1`, `우 1`, `앞`, `뒤`, `전체` 등 범위 용어의 표준
- 빈 슬롯을 관통하는 공격 여부
- 1번 또는 4번 바깥으로 나간 범위의 처리
- 보스 5번이 모든 1~4번 슬롯과 인접한지 여부
- 보스가 범위 공격의 중심일 때 1~4번 전체가 피격되는지 여부

## 10. 일반 전투와 보스전

### 10.1 일반 전투

- 1~4번 슬롯에 일반 몬스터를 배치한다.
- 실제 출현 수는 전투 데이터에 따라 1~4마리이다.
- 살아 있는 모든 적을 처치하면 승리한다.

### 10.2 보스전

- 5번 슬롯에는 보스를 배치한다.
- 1~4번 슬롯에는 부하 몬스터가 등장할 수 있다.
- 보스를 처치하는 즉시 승리 조건을 달성한다.
- 1~4번 슬롯에 부하 몬스터가 남아 있어도 모두 처치할 필요는 없다.
- 보스 사망이 확정되면 남아 있는 부하의 행동 대기열을 취소하고 승리 연출로 전환한다.

### 10.3 보스전의 전술적 선택

| 전략 | 설명 |
|---|---|
| 안정형 | 부하를 먼저 제거한 뒤 보스를 공략 |
| 범위형 | 부하와 보스를 동시에 공격 |
| 집중형 | 부하의 위협을 감수하고 보스만 빠르게 처치 |

보스전의 슬롯과 범위 규칙은 위 세 전략이 모두 의미 있는 선택이 되도록 설계한다.

## 11. 몬스터 행동 시스템

### 11.1 데이터 기준

몬스터 행동은 Blockable Monster Designer가 생성한 JSON의 `behavior` 구조를 따른다.

참고 예제:

<https://github.com/Nyamkani/Blockable_Monster_Designer/blob/main/examples/examples.json>

전투 엔진은 다음 역할만 담당한다.

1. 몬스터의 현재 페이즈와 패턴 위치를 읽는다.
2. 이번 행동에 사용할 `ability_id`를 결정한다.
3. 선택된 능력의 사용 가능 조건과 쿨다운을 검사한다.
4. 해당 능력의 의도를 UI에 표시한다.
5. 능력의 효과를 정해진 순서로 실행한다.
6. 패턴 위치, 쿨다운, 트리거와 페이즈 상태를 갱신한다.

### 11.2 기본 데이터 구조

현재 예제의 주요 구조는 다음과 같다.

```text
monster
├─ stats
├─ abilities
│  ├─ effects
│  ├─ intent
│  ├─ availability_condition
│  └─ cooldown_turns
└─ behavior
   ├─ initial_phase_id
   └─ phases
      ├─ loop
      │  ├─ mode
      │  ├─ fallback_ability_id
      │  └─ steps
      └─ triggers
```

이 구조는 Monster Designer의 실제 스키마가 변경되면 함께 갱신해야 한다.

### 11.3 행동 단계 유형

최소한 다음 두 종류의 행동 단계를 지원한다.

| 단계 유형 | 동작 |
|---|---|
| `ability` | 지정된 능력을 확정적으로 선택 |
| `random_choice` | 가중치 또는 확률에 따라 능력을 선택 |

따라서 하나의 몬스터는 완전한 연속형 또는 완전한 확률형으로만 제한되지 않는다. 하나의 순환 패턴 안에 확정 행동과 확률 행동을 함께 배치할 수 있다.

예:

```text
기본 공격
→ 특수 공격
→ 확률 선택
   ├─ 특수 공격 80%
   └─ 자가 회복 20%
→ 처음부터 반복
```

### 11.4 행동 결정과 실행의 분리

다음 행동의 결정 시점과 실제 실행 시점을 분리한다.

```text
행동 결정
→ intent 표시
→ 플레이어 턴
→ 몬스터 행동 차례
→ 예약된 ability 실행
→ 다음 행동 결정
```

플레이어가 보고 전략을 세울 수 있도록, 표시된 의도는 원칙적으로 해당 몬스터 행동 직전까지 유지한다.

행동 불가 상태, 페이즈 변경 또는 트리거로 예약 행동이 바뀔 수 있다면 UI에 변경을 즉시 반영한다.

### 11.5 능력 실행

능력 실행 시 다음 순서를 따른다.

1. 능력 ID 유효성 검사
2. 생존 및 행동 가능 상태 검사
3. 사용 조건 검사
4. 쿨다운 검사
5. 대상 결정
6. 대형 이미지 전환
7. `animation_id` 실행
8. 능력의 `effects`를 `order` 순서로 적용
9. 피해·회복·상태 변화 표시
10. 사망 및 전투 종료 판정
11. 쿨다운과 런타임 상태 갱신
12. 행동 패턴 위치 진행

능력을 사용할 수 없다면 `fallback_ability_id`가 존재할 경우 대체 능력을 사용한다. 대체 능력도 실행할 수 없다면 해당 몬스터의 행동을 건너뛰고 오류 로그를 남긴다.

### 11.6 확률 선택

- 모든 가중치는 0보다 큰 값만 유효하게 취급한다.
- 선택 가능한 항목의 유효 가중치 합계를 기준으로 정규화한다.
- 사용 조건을 만족하지 않는 능력은 추첨 후보에서 제외한다.
- 모든 후보가 제외되면 `fallback_ability_id`를 사용한다.
- 재현 가능한 테스트를 위해 난수 시드를 주입할 수 있어야 한다.
- UI에는 확률 후보 전체가 아니라 실제로 예약된 다음 행동 의도를 표시한다.

### 11.7 페이즈와 트리거

- 전투 시작 시 `initial_phase_id`를 사용한다.
- 트리거가 성립하면 지정된 페이즈로 전환할 수 있다.
- 페이즈 변경 시 패턴 위치의 초기화 또는 유지 여부는 데이터 규칙을 따른다.
- 같은 시점에 여러 트리거가 성립할 경우 우선순위 규칙이 필요하다.
- 무한 페이즈 전환을 막기 위해 한 번의 상태 처리에서 허용되는 전환 횟수에 상한을 둔다.

### 11.8 몬스터 행동 실행 상태

몬스터의 행동 패턴 FSM과 실제 행동 실행 상태를 분리한다.

- 행동 패턴 FSM은 이번 턴에 어떤 `ability_id`를 예약할지 결정한다.
- 행동 실행 상태는 예약된 행동이 실제로 실행, 취소 또는 기절로 건너뛰어졌는지 관리한다.

권장 실행 상태:

```text
IDLE
→ INTENT_READY
→ QUEUED
→ ACTING
→ RESOLVED

QUEUED → STUN_SKIPPED
QUEUED → CANCELLED
모든 상태 → DEAD
```

| 상태 | 의미 |
|---|---|
| `IDLE` | 다음 행동이 아직 결정되지 않음 |
| `INTENT_READY` | 다음 `ability_id`가 결정되어 UI에 공개됨 |
| `QUEUED` | 이번 몬스터 행동 대기열에 등록됨 |
| `ACTING` | 능력 효과를 실행 중 |
| `RESOLVED` | 정상적으로 행동을 완료함 |
| `STUN_SKIPPED` | 기절을 소비하고 예약 행동을 실행하지 않음 |
| `CANCELLED` | 사망, 전투 종료 또는 유효성 실패로 행동이 취소됨 |
| `DEAD` | 사망하여 더 이상 행동할 수 없음 |

기절은 행동 패턴 자체를 별도 페이즈로 바꾸지 않는다. `QUEUED` 상태의 실행 직전에 기절을 확인해 `STUN_SKIPPED`로 전환하고, 기절을 제거한 뒤 패턴 위치만 다음 단계로 진행한다.

## 12. 몬스터 행동 순서와 대기열

다수 몬스터가 존재할 때 행동은 한 마리씩 순서대로 연출하고 처리한다.

권장 런타임 구조:

```text
MonsterActionQueue
[
  { slotId, monsterId, abilityId, targetIds },
  ...
]
```

### 12.1 기본 원칙

- 해커톤 프로토타입의 행동 순서는 1번부터 4번 슬롯 순서이며, 보스전에서는 5번 보스가 마지막에 행동한다.
- 동시 행동은 사용하지 않고 한 마리씩 순차 처리한다.
- 행동 대기열에 들어간 뒤 몬스터가 사망하면 해당 행동을 취소한다.
- 기절 등 행동 불가 상태가 되면 실행 직전에 다시 검사한다.
- 보스 사망으로 전투가 종료되면 남은 행동을 모두 취소한다.
- 플레이어 사망이 확정되면 남은 행동을 중단한다.

### 12.2 미확정 항목

- 플레이어의 반응 또는 차단 효과가 대기열에 개입하는 방식
- 장기 확장에서 속도 능력치를 도입할지 여부

## 13. 몬스터 이미지와 UI

### 13.1 소형 슬롯

1~4번 슬롯과 보스전의 5번 슬롯은 전체 전황과 대상 선택을 담당한다.

각 소형 슬롯에는 다음 정보를 표시한다.

- 소형 몬스터 이미지
- 슬롯 번호
- 이름 또는 간략 식별 정보
- HP 바와 현재 HP
- 다음 행동 아이콘
- 버프·디버프 아이콘
- 사망 여부
- 현재 선택 여부
- 직접 대상 또는 범위 대상 여부

5번 보스 슬롯은 더 큰 크기와 별도의 보스 HP 표시를 사용할 수 있다.

### 13.2 대형 이미지 영역

기존 전투 화면 오른쪽의 큰 몬스터 이미지는 유지한다.

대형 이미지 영역은 실제 전투 슬롯이나 충돌 판정 영역이 아니라, 선택·공격·피격 몬스터를 확대해 보여주는 공용 연출 영역이다.

대형 이미지 표시 우선순위:

1. 현재 행동 중인 몬스터
2. 현재 피격 연출 중인 몬스터
3. 플레이어가 선택한 몬스터
4. 기본 대상
   - 일반 전투: 1번 또는 기본 선택 몬스터
   - 보스전: 5번 보스

예:

```text
2번 몬스터 선택 이미지
→ 4번 몬스터 공격 이미지
→ 플레이어 피격 연출
→ 2번 몬스터 선택 이미지로 복귀
```

행동 연출이 끝난 뒤에는 사용자가 마지막으로 선택한 살아 있는 몬스터로 복귀한다. 해당 몬스터가 사망했다면 기본 대상 선택 규칙을 다시 적용한다.

## 14. 이미지 리소스와 애니메이션 구조

### 14.1 설계 원칙

현재 해커톤 버전에서는 몬스터마다 여러 이미지나 프레임 애니메이션을 제작하지 않는다. 그러나 향후 확장을 위해 데이터 구조는 상태별 이미지와 능력별 애니메이션을 지원하도록 만든다.

행동 패턴과 화면 표현은 분리한다.

```text
behavior / ability
→ 몬스터가 무엇을 하는가

visuals / animation_id
→ 그 행동을 화면에 어떻게 보여주는가
```

### 14.2 `visuals`

권장 구조:

```json
{
  "visuals": {
    "idle": "ember_slime",
    "attack": null,
    "hit": null,
    "dead": null
  }
}
```

초기 버전에서는 `idle`만 실제 이미지에 연결해도 된다.

| 상태 | 용도 | 초기 폴백 |
|---|---|---|
| `idle` | 평상시 및 선택 상태 | 필수 기본 이미지 |
| `attack` | 공격 상태 | `idle` |
| `hit` | 피격 상태 | `idle` |
| `dead` | 사망 상태 | `idle` 후 CSS 연출 |

### 14.3 `animation_id`

`animation_id`는 별도 이미지 파일이 아니라 현재 이미지를 움직이는 공통 연출 프리셋을 의미할 수 있다.

```json
{
  "id": "basic_attack",
  "animation_id": "lunge_left"
}
```

초기 공통 프리셋:

| `animation_id` | 임시 연출 |
|---|---|
| `lunge_left` | 플레이어 방향인 왼쪽으로 살짝 돌진한 뒤 복귀 |
| `pulse` | 제자리에서 확대·축소 |
| `shake` | 좌우 흔들림 |
| `flash` | 짧은 밝기 또는 색상 점멸 |
| `fade_out` | 투명도를 낮추며 사라짐 |
| `none` | 별도 연출 없음 |

### 14.4 폴백 규칙

```text
ability.animation_id 존재
→ 지정된 공통 애니메이션 실행

animation_id 없음 + 공격 능력
→ lunge_left

animation_id 없음 + 회복·버프 능력
→ pulse

visuals의 상태별 이미지 존재
→ 해당 이미지 사용

상태별 이미지 없음
→ idle 이미지 유지
```

### 14.5 공격 연출

1. 행동할 몬스터를 대형 이미지 영역에 표시한다.
2. 능력의 `animation_id`를 확인한다.
3. `lunge_left`라면 이미지를 플레이어 방향으로 이동시킨다.
4. 돌진 정점에서 실제 피해 또는 효과를 적용한다.
5. 이미지를 원래 위치로 복귀시킨다.
6. 다음 행동 또는 기존 선택 이미지로 전환한다.

공격 판정 시점은 CSS 애니메이션 종료 이벤트에만 의존하지 않는다. 전투 엔진이 명시적인 타이밍 이벤트를 발생시키고, UI는 해당 이벤트에 맞춰 연출한다.

### 14.6 피격과 사망 연출

현재 이미지 한 장으로 다음 연출을 사용한다.

```text
피격
→ shake + flash

사망
→ 축소 또는 아래로 가라앉음
→ fade_out
→ 소형 슬롯에 처치 상태 표시
```

전투 판정은 연출 완료를 기다리지 않고 확정 상태를 먼저 기록해야 한다. 연출 중 입력과 중복 피해가 발생하지 않도록 상태를 잠근다.

## 15. 의도(Intent) 표시

몬스터의 다음 행동은 능력 데이터의 `intent`를 이용해 표시한다.

의도 UI는 최소한 다음 정보를 표현할 수 있어야 한다.

- 공격
- 방어
- 버프
- 디버프
- 회복
- 특수 행동
- 대상
- 예상 타격 횟수

정확한 피해 수치를 사전에 표시할지 여부는 미확정이다.

의도 표시와 실제 실행 결과가 달라질 수 있는 경우에는 다음 중 하나를 적용한다.

- 의도 변경 즉시 UI 갱신
- 불확정 행동 아이콘 표시
- 조건부 행동임을 툴팁으로 표시

초기 버전에서는 실제로 예약된 `ability_id`의 의도를 그대로 표시하는 방식을 사용한다.

## 16. 전투 런타임 상태

정적 데이터와 전투 중 변경되는 상태를 분리한다.

### 16.1 정적 데이터

```text
MonsterDefinition
BlockDefinition
AbilityDefinition
BehaviorDefinition
VisualDefinition
AnimationPresetDefinition
```

정적 데이터는 원본 JSON을 직접 변경하지 않는다.

### 16.2 런타임 데이터

```text
CombatState
PlayerCombatState
MonsterCombatState[]
BoardState
TargetingState
ActionQueue
AnimationState
CombatLog
```

몬스터 런타임 상태 예시:

```ts
type MonsterCombatState = {
  instanceId: string;
  monsterId: string;
  slotId: 1 | 2 | 3 | 4 | 5;
  currentHp: number;
  currentArmor: number;
  buffs: RuntimeEffect[];
  debuffs: RuntimeEffect[];
  currentPhaseId: string;
  currentStepIndex: number;
  cooldowns: Record<string, number>;
  plannedAbilityId: string | null;
  actionExecutionState:
    | "idle"
    | "intent_ready"
    | "queued"
    | "acting"
    | "resolved"
    | "stun_skipped"
    | "cancelled"
    | "dead";
  isAlive: boolean;
  canAct: boolean;
};
```

상태 효과 런타임 예시:

```ts
type RuntimeStatus = {
  statusId: "weakness" | "wound" | "stun" | "bleed" | "burn";
  stacks: number;
  appliedTurnId: number;
  newlyAppliedStacks: number;
  hasAffectedDamageCalculation: boolean;
};
```

전투 상태 예시:

```ts
type CombatState = {
  battleType: "normal" | "boss";
  phase:
    | "initializing"
    | "player_turn"
    | "resolving_player_action"
    | "monster_turn"
    | "resolving_monster_action"
    | "resolving_turn_end_status"
    | "victory"
    | "defeat";
  turnNumber: number;
  player: PlayerCombatState;
  monsters: MonsterCombatState[];

  remainingPlacements: number;

  extraTurnReserved: boolean;
  actionQueue: CombatAction[];
};
```

위 코드는 구현 방향을 설명하는 예시이며, 프로젝트의 실제 타입 구조에 맞게 조정할 수 있다.

## 17. 이벤트 기반 처리

전투 판정과 화면 연출의 결합을 줄이기 위해 이벤트 기반 처리를 권장한다.

예시 이벤트:

```text
COMBAT_STARTED
PLAYER_TURN_STARTED
BLOCK_PLACED
COMBO_CREATED
TARGET_PREVIEW_CHANGED
PLAYER_ACTION_CONFIRMED
DAMAGE_APPLIED
HEAL_APPLIED
STATUS_APPLIED
STATUS_DAMAGE_APPLIED
STATUS_STACK_DECAYED
STUN_CONSUMED
MONSTER_ACTION_SKIPPED
TURN_END_STATUS_STARTED
TURN_END_STATUS_FINISHED
MONSTER_ACTION_STARTED
MONSTER_ACTION_IMPACT
MONSTER_ACTION_FINISHED
MONSTER_DIED
BOSS_DIED
COMBAT_VICTORY
COMBAT_DEFEAT
```

전투 엔진은 결과를 결정하고, React와 Phaser는 이벤트를 구독해 UI와 연출을 갱신한다.

```text
Combat Engine
→ 전투 상태 변경
→ 전투 이벤트 발행
→ React HUD 갱신
→ Phaser 이미지·효과 재생
```

React와 Phaser 양쪽에서 같은 피해 계산을 다시 수행하지 않는다. 전투 결과의 단일 기준은 전투 엔진이다.

## 18. 예외 및 유효성 규칙

### 18.1 슬롯

- 일반 전투에 5번 슬롯 몬스터를 생성하지 않는다.
- 보스전의 5번 슬롯에는 정확히 한 명의 보스를 배치한다.
- 같은 슬롯에 둘 이상의 살아 있는 몬스터를 배치하지 않는다.
- 전투 중 슬롯 번호를 변경하지 않는다.

### 18.2 대상

- 사망한 몬스터를 직접 대상으로 선택할 수 없다.
- 대상이 행동 확정 전에 사망하면 유효한 기본 대상으로 재선택한다.
- 유효한 대상이 없으면 공격 행동을 실행하지 않고 승리 조건을 먼저 검사한다.
- 범위 대상 목록에는 같은 몬스터를 중복 추가하지 않는다.

### 18.3 행동 데이터

- 존재하지 않는 `ability_id`는 실행하지 않는다.
- 존재하지 않는 `phase_id`로 이동하지 않는다.
- 빈 확률 선택 목록은 오류로 처리한다.
- 가중치 합이 0 이하이면 폴백 능력을 사용한다.
- 쿨다운 또는 사용 조건으로 모든 능력이 막히면 폴백 규칙을 적용한다.
- 폴백 능력도 유효하지 않으면 행동을 건너뛰고 진단 로그를 남긴다.

### 18.4 전투 종료

- 일반 전투는 현재 효과와 사망·연쇄 효과 대기열이 모두 끝난 뒤 살아 있는 적이 0명이고 플레이어가 살아 있으면 승리한다.
- 보스전은 5번 보스가 사망하는 순간 승리한다.
- 승리·패배 상태는 한 번만 확정한다.
- 종료 상태 이후의 예약 피해와 상태 효과는 적용하지 않는다.
- 전투 종료 연출 중 플레이어 입력으로 추가 행동을 생성할 수 없다.

### 18.5 애니메이션

- 존재하지 않는 `animation_id`는 기본 폴백을 사용한다.
- 애니메이션이 실패해도 전투 로직은 계속 진행되어야 한다.
- 브라우저 탭 비활성화 등으로 애니메이션 이벤트가 누락되어도 전투가 멈추지 않아야 한다.
- 동일 몬스터에 공격·피격·사망 연출이 겹치면 사망 연출을 가장 높은 우선순위로 처리한다.

## 19. 구현 단계

### 1단계: 전투 상태와 슬롯

- 일반전·보스전 구분
- 몬스터 인스턴스 생성
- 1~5번 고정 슬롯
- 대상 선택
- 일반전·보스전 승리 조건

### 2단계: 플레이어 공격

- 블록 배치 횟수
- 직접 대상과 범위 대상 미리 보기
- `B`, `P`, `H`, `M`, `D`, `W` 기본 공격 계산
- `A`, `M`, `D`, `W` 독립 공격 계산과 별도 타겟팅
- 대상 사망·무효화 시 남은 연타 및 공격 기회 종료
- 방어도 우선 차감과 체력 피해
- 콤보 및 동일 색상 보너스
- 피격 및 사망 처리

### 3단계: 몬스터 행동

- Monster Designer JSON 로드
- `ability` 단계
- `random_choice` 단계
- 행동 의도 표시
- 효과 `order` 순차 실행
- 쿨다운과 폴백

### 4단계: 다수 몬스터 대기열

- 몬스터별 예약 행동
- 순차 행동
- 행동 실행 상태와 기절 소비
- 사망 시 취소
- 행동 사이의 전투 종료 검사

### 5단계: 턴 종료 상태이상

- 출혈과 화상 피해
- 약화와 상처의 피해 계산 참여 여부
- 상태별 스택 감소
- 상태이상 사망과 연쇄 대기열
- 보스 상태이상 사망 즉시 종료

### 6단계: 이미지 연출

- 소형 슬롯 이미지
- 선택 몬스터 대형 이미지
- `visuals` 폴백
- `lunge_left`
- `pulse`
- `shake + flash`
- 사망 `fade_out`

### 7단계: 페이즈와 고급 조건

- 행동 페이즈
- 트리거
- 조건부 능력
- 행동 변경 시 intent 갱신
- 데이터 유효성 검사와 오류 표시

## 20. 최소 완료 조건

다음 항목이 모두 동작하면 전투 시스템의 1차 구현이 완료된 것으로 본다.

- 일반 전투에서 1~4마리 몬스터를 고정 슬롯에 표시할 수 있다.
- 슬롯을 클릭하면 직접 대상과 대형 이미지가 변경된다.
- 공격 실행 전 직접 대상과 범위 대상을 구분해 표시한다.
- 기본 공격은 `(B + P) × M × D × W`를 H회 개별 실행한다.
- `A`는 기본 공격의 모든 처리가 끝난 뒤 `A × M × D × W`로 계산해 자체 타겟팅으로 실행한다.
- 기본 공격 대상이 사망·무효화되면 남은 연타와 해당 공격 기회를 다른 적에게 재지정하지 않는다.
- 분노 1스택당 공격력 `+1`, 철갑 1스택당 방어도 `+1`이 적용된다.
- 일반 피해는 방어도를 먼저 소모하고 초과 피해만 체력에 적용된다.
- 약화와 상처가 각각 `D`와 `W`에 적용된다.
- 출혈과 화상이 턴 종료 단계에서 정해진 순서와 감소 규칙으로 처리된다.
- 기절한 몬스터는 현재 행동을 건너뛰고 기절을 소비하며 패턴 위치를 진행한다.
- Monster Designer JSON에 따라 연속형과 확률 선택이 포함된 행동을 실행한다.
- 각 몬스터의 다음 행동 의도를 표시한다.
- 몬스터들이 대기열에 따라 한 마리씩 행동한다.
- 공격 몬스터가 대형 이미지에 표시되고 왼쪽으로 살짝 돌진한다.
- 피격 시 동일 이미지로 흔들림과 점멸 효과가 실행된다.
- 사망한 슬롯은 빈자리로 남고 다른 몬스터가 이동하지 않는다.
- 일반전에서는 모든 적 처치 시 승리한다.
- 보스전에서는 5번 보스 처치 즉시 승리한다.
- 보스 사망 시 남은 부하의 행동이 취소된다.
- 이미지나 애니메이션 데이터가 누락되어도 폴백으로 전투를 끝까지 진행할 수 있다.

## 21. 필수 테스트 시나리오

### 21.1 일반 전투

1. 몬스터 1마리 전투
2. 몬스터 4마리 전투
3. 중간 슬롯 몬스터 사망 후 빈자리 유지
4. 선택한 몬스터 사망 후 남은 연타 종료 및 자동 재지정 금지
5. 마지막 몬스터 사망 후 사망·연쇄 대기열 완료 및 승리
6. 마지막 몬스터 사망 효과로 플레이어도 사망하여 패배

### 21.2 범위 공격

1. 직접 대상만 공격
2. 인접 슬롯 동시 공격
3. 빈 슬롯이 포함된 범위
4. 사망 슬롯이 포함된 범위
5. 보스와 부하가 함께 포함되는 범위
6. 동일 대상 중복 방지

### 21.3 몬스터 행동

1. 고정 능력 순환
2. 고정 행동과 확률 선택의 혼합 순환
3. 동일 시드에서 같은 확률 결과 재현
4. 사용 조건 불충족 후 폴백
5. 쿨다운 중인 능력 제외
6. 존재하지 않는 능력 ID 처리
7. 행동 직전 몬스터 사망으로 대기열 취소
8. 기절로 행동을 건너뛴 뒤 기절 제거
9. 기절로 건너뛴 행동의 패턴 위치 진행
10. 사망한 몬스터의 기절이 소비되지 않음

### 21.4 보스전

1. 보스만 존재하는 전투
2. 보스와 부하 4마리 전투
3. 부하를 모두 처치한 뒤 보스 처치
4. 부하가 남은 상태에서 보스 집중 처치
5. 보스 사망 직후 남은 부하 행동 취소
6. 보스의 턴 종료 상태이상 사망 직후 남은 상태이상 처리 취소

### 21.5 피해와 상태이상

1. `B`, `P`, `H`, `M`, `D`, `W`의 기본 공격 중간값 검증
2. 기본 공격이 H개의 개별 공격으로 처리됨
3. 중심 대상 사망 시 남은 연타와 해당 공격 기회가 다른 적에게 재지정되지 않음
4. `A`가 기본 공격 완료 뒤 독립 공격으로 실행되고 H의 영향을 받지 않음
5. 기본 공격 대상 사망 뒤에도 `A`가 자체 타겟팅으로 판정됨
6. 약화 여러 스택의 감쇄율 합산과 `D` 하한 `0`
7. 대상별 상처 스택에 따라 범위 공격의 `W`가 다르게 적용됨
8. 방어도보다 작은, 같은, 큰 일반 피해
9. 방어도 무시 피해가 방어도를 보존하고 체력만 감소시킴
10. 출혈이 이번 턴 확정 배치 블록 수와 감소 전 스택으로 계산됨
11. 화상이 방어도를 소모하고 처리 후 `floor(stacks / 2)`로 감소함
12. 이번 턴 새로 부여된 출혈·화상이 같은 턴 종료에 발동함
13. 아직 피해 계산에 참여하지 않은 새 약화·상처가 감소하지 않음
14. 출혈로 사망한 대상의 화상 처리가 중단됨
15. 상태이상 사망 효과가 연쇄 대기열에 등록됨

### 21.6 연출 폴백

1. `idle` 이미지만 존재
2. `animation_id`가 없음
3. 존재하지 않는 `animation_id`
4. 애니메이션 도중 대상 사망
5. 애니메이션 완료 이벤트 누락

## 23. 최종 설계 원칙

1. 개별 몬스터 행동은 코드가 아니라 Monster Designer JSON을 기준으로 한다.
2. 몬스터의 행동 결정과 화면 연출을 분리한다.
3. 소형 슬롯은 전황과 판정을, 대형 이미지는 선택과 행동 연출을 담당한다.
4. 슬롯은 전투 도중 재정렬하지 않는다.
5. 공격 실행 전 모든 직접·범위 대상을 표시한다.
6. 일반 전투와 보스전의 승리 조건을 명확히 분리한다.
7. 보스전은 부하 제거와 보스 집중 공격이 모두 가능한 구조로 만든다.
8. 현재는 몬스터 이미지 한 장만 사용하되 `visuals`와 `animation_id` 확장 구조를 유지한다.
9. 애니메이션 실패나 리소스 누락이 전투 로직을 중단시키지 않게 한다.
10. React, Phaser, 전투 엔진 중 전투 결과의 단일 기준은 전투 엔진으로 유지한다.
